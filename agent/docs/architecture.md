# 自主科研 Agent：结构、执行流程与能力边界

本分支只维护通用 Agent：`agent/` 随科研策略演进，`research/` 保存本地研究材料，课题专用实现及依赖在独立仓库或其他分支维护。不把历史课题需求上移成所有研究的硬门禁。

## 控制平面模块

```text
agent/runtime/research/
  policy.py          schema/gate-policy 版本、文件布局、阶段与转换表
  storage.py         JSON/JSONL、项目锁、事件链和项目路径定位
  execution.py       冻结文件集合、版本授权、run 产物核验和实证状态推导
  gates.py           科学材料的结构检查及统一阶段门禁
  researchctl.py     命令解析、状态变更和事件登记
  audit.py           只读审计入口，共用 gates.py
  collect_openalex.py 调用方配置驱动的文献发现工具
  taskqueue.py       宿主驱动的证据任务、依赖版本与恢复记录
```

依赖从 policy、storage 指向 execution，再指向 gates 和 CLI；底层模块不导入 CLI，也不导入任何课题模块。为兼容已有调用方，`researchctl.py` 暂时重导出原有函数；新代码优先从其所属模块导入。

此次拆分针对已发现的故障边界：审计与状态转换不再分别维护阶段阈值，协议冻结和执行验证不再散落在命令实现中，实证进度统一从运行证据计算。没有为每种课题引入插件框架或独立服务，避免增加尚无实际调用需求的层级。

## 已固化的不变量

- 设计、分析计划、理论预测等冻结成员必须同时校验当前文件、归档、协议锁及事件。
- 执行指令证据与具体协议版本绑定；资源权限来自冻结设计中的显式声明。
- 主实验不能只靠 Markdown 中的 `pass` 进入，需要当前协议的可核验 Pilot 运行。
- 阶段变更不等于实验完成；机器实证状态来自登记终局、阶段、配置与结果哈希。
- 外部、生成和无数据研究分别描述材料来源，不强迫固定数据集数量或课题专用章节。
- 门禁策略升级必须显式迁移，并保存旧材料；旧记录不被补写成已满足新版要求。

## 测试分层

`agent/tests/test_researchctl.py` 保留原控制平面回归；`agent/tests/test_topic_independence.py` 检查算法、系统与理论问题使用相同协议入口；`agent/tests/test_execution.py` 验证绕过路径和真实的状态转换，全部使用临时项目和模拟产物，不执行研究实验。课题专用测试随课题实现维护，不再纳入本分支。默认测试通过只证明这些实现性质，不证明研究内容正确。

## 自主科研的实现边界与开发优先级

目标产品是能持续执行科研任务的 Agent，当前已有 Skills、工具和控制平面，由宿主 Agent 负责实际编排。状态机记录了阶段，不意味着它能独立选择任务、检索、阅读和实验。Skills 能指导宿主自主工作；要脱离当前会话长期运行，还需要执行服务及可靠恢复机制。两者应分别验收。

| 能力 | 当前代码/流程具备什么 | 仍缺什么 | 可观察的验收目标 |
|---|---|---|---|
| 持续编排与任务选择 | Skills规定阶段；researchctl管理阶段；taskqueue持久保存任务和依赖 | 独立执行循环、工具结果驱动的任务选择 | 一次提交目标后完成必要取证与交接；新增反证能改变下一动作，而非只重写计划 |
| 中断恢复与避免重复执行 | 事件链、项目锁、run登记；任务排他领取、凭证撤销、显式恢复/取消和尝试历史 | 自动外部任务对账、进程心跳及执行器级幂等保证 | 工具提交后进程崩溃，重启能找回原任务且不重复启动；失联任务有明确处置 |
| 可复用的检索与阅读工具 | OpenAlex候选采集、阅读Skill和来源约束 | 稳定的多来源检索、全文/图表解析接口、访问失败恢复及阅读范围记录 | 不依赖某课题临时脚本就能定位正文、核查关键原图并保留访问缺口 |
| 证据记忆与依赖更新 | 论文卡、claim ID、协议哈希；任务输入/输出哈希和传递依赖失效检查 | 声明级语义依赖、自动发现未登记引用，以及来源变化后的科学复核 | 关键来源换版或结论撤回时，定位受影响主张和报告，保留旧解释，避免沿用过期结论 |
| 科研语义验收与审查隔离 | 科学审查契约；gates/audit检查材料结构 | 可信角色隔离、原文支持度/推导正确性检查、审查分歧处理 | 引用存在但不支持主张时能拒绝；生成者不能通过填写另一个角色名字自签验收 |
| 实验执行与实际资源管理 | 协议授权、run准入、预算预留、完成后用量登记 | 可启动/监控/取消的执行器，实时资源采集，超时和预算停止，模型/API用量核算 | 登记的run对应真实进程和产物；实际超预算能及时停止并如实记账，而非只事后报告 |
| 科研能力评测 | 代码回归测试与行为验收清单 | 在未见问题上的实际任务评测、人工核验的关键事实/反证、失败归因 | 分别测来源正确性、正文理解、推断、任务完成及资源成本；包含中断和负结果场景 |

实现依据：`researchctl.py` 的 `command_run` 检查调用方提供的资源预留并登记queued，`command_finish_run` 用调用方提供的实际用量结算；这不是进程启动或资源遥测。`execution.py`校验授权与产物；`audit.py`/`gates.py`检查结构及声明契约，不读取论文并判定科学正确性。上述缺口是本地实现审查，不宣称已经完成对应能力实验。

### 建议的开发顺序

先建立一个能完成调研阶段的最小自主闭环：持久任务队列 → 真实检索/阅读调用 → 结果核验 → 下一任务选择 → 断点恢复。先接入一条实际可用的宿主/模型调用路径，不以空执行器或模拟状态转换作为闭环完成。

随后接入证据依赖更新和隔离审查，并在未见问题上做语义验收。最后把已获授权的实验执行器、实时用量与停止机制接入同一闭环，扩展到完整研究。控制平面的既有门禁持续生效，不能为了自动推进而降低质量标准。

当前每轮循环已写入迭代科研 Skill；`taskqueue.py` 已实现持久证据任务，但不调用模型、调度进程或授予实验权限。任务记录仅在使用时创建为 `control/tasks.json`，采用独立 version=1 格式，不改变研究 schema/gate-policy，不推进科研阶段。输入/输出与依赖变化会令 `usable=false` 并返回原因，保留历史完成记录；宿主须复核科学影响。队列变更共用事件完整性与策略版本检查；拓扑校验拒绝损坏依赖，来源路径拒绝符号链接，取消不要求丢失输入重新出现。持久记录不等于无人值守服务，实际遥测与独立执行循环仍待实现。

课题源码、数据适配器和专用环境继续独立维护；自主编排不意味着把具体课题内置到通用 Agent。

## 调研流程改进的工程依据

以下仅记录设计取舍，不是新的研究课题或这些系统的完整文献综述。2026-09-09 补查官方实现与技术说明：

| 来源 | 可借鉴的机制 | 本仓库落点与边界 |
|---|---|---|
| [PaperQA2 官方仓库](https://github.com/Future-House/paper-qa#paperqa2-algorithm) | 工具驱动搜索、证据收集、回答，允许按需要反复调用 | 每轮选择证据问题，任务登记输入和验收产物；尚未接入其全文索引或模型调用 |
| [AI Scientist v2 官方仓库](https://github.com/SakanaAI/AI-Scientist-v2) | 实验管理器引导渐进树搜索 | 保留候选与失败尝试，按问题拆分依赖任务；没有宣称实现实验树搜索 |
| [Google co-scientist 官方说明](https://research.google/blog/accelerating-scientific-breakthroughs-with-an-ai-co-scientist/) | Supervisor/worker queue；生成、批评、排名和修订 | 增加持久任务队列；保留生成与审计分离要求，领取 owner 不作为可信身份或独立审计证明 |

工程取舍：先做宿主可直接使用的任务恢复和版本核验，不引入这些系统的整套依赖；自评分、轮数和工具成功状态均不能替代科研证据。

- 从 [PaperQA2](https://arxiv.org/html/2409.13740v1) 的取证循环借鉴问题驱动检索，已落实到 `scholarly-search` 的问题队列与补检条件。
- 从 [Co-Scientist](https://www.nature.com/articles/s41586-026-10644-y) 的假设核验与反馈积累借鉴逐项检查，已落实到论文卡的实际阅读记录和跨轮纠错。
- [Kosmos](https://arxiv.org/html/2511.02824v1) 的来源记忆与解释错误说明可追溯性仍需语义复核，已落实到 `evidence-synthesis` 的原文回查。

这些规则尚不等于独立自主执行能力已实现，也未通过对照实验验证质量提升。此前误建的流程研究目录已取消；不把论文缓存搬入通用 Agent。工程验收场景见 `agent/docs/evals.md`。

事件链不是签名，也不能防止拥有写权限的人重写全部历史。授权证据内容与独立审查质量仍需要可信编排和人工监督；文件格式与哈希不能替代科学判断。

## 仓库入口

根目录仅保留 `AGENTS.md`、`README.md` 和 `agent/` 作为可见源码入口；实际课题创建后才出现 `research/`。`agent/` 顶层只保留 `skills/`、`runtime/`、`tests/`、`docs/` 和 `check.py`。测试依赖与 pytest 配置随测试放在 `tests/`；行为验收文档放在 `docs/evals.md`；PowerShell 审计入口与 Python 实现在 `runtime/research/` 同目录。运行时仅依赖标准库，不保留空依赖清单。使用 `python agent/check.py` 运行检查，也可执行 `python -m pytest -c agent/tests/pytest.ini`；CI 使用同一入口。`.github/` 保留在 GitHub 要求的位置，用于 CI；`.git/` 和 `.gitignore` 用于版本管理。

## 可选文档导出

`runtime/documents/` 提供独立的 Markdown→PDF 命令、打印样式和 Node 依赖声明，由 evidence-synthesis 的文档导出契约调用。它接受显式源文件、目标路径与字体，保留公式和正文顺序，校验失败不覆盖旧PDF；不改变科研阶段，不内置课题内容，也不要求Python科研运行时加载浏览器依赖。
