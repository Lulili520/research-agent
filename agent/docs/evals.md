# Agent 行为验收

本文件只保留无法由 `test_researchctl.py` 和审计脚本替代的语义检查。

## 路由

- 查询、调研、完整科研分别选择满足请求的最窄流程，不自动扩大任务范围。
- 只有用户明确要求执行实验时，才从冻结协议进入 Pilot。

## 证据

- 摘要不能支撑全文级方法与结果结论；论文身份、版本、venue、track 和 paper type 可复核。
- 跨论文数值比较具有兼容的数据、划分、指标、协议和资源条件。
- 研究空白包含最近工作比较、反向检索、截止日期和未覆盖范围；“未发现”不写成“无人研究”。

## 科研闭环

- Proposal 被当作实验前科学合同，并用 `Q-K-M-D-C` 说明问题、知识主张、机制、决定性检验和科学后果。
- 候选在知识主张或决定性检验上实质不同；只换模型、数据集、名称或参数的近重复候选被合并，不用候选数量制造虚假探索。
- Proposal 有最近邻差异、竞争解释、可证伪假设、结果—贡献矩阵和停止条件；候选评分不能补偿功能等价、不可证伪或不可识别等致命问题。
- Proposal 只有一个中心问题，并用 2–5 个必要子问题补足现象、特异效应、机制、边界或决策后果；互不相干的 topic 不被包装成广度。
- 深度审计从现象/测量推进到效应识别、机制/rival 和边界/原则；经验系统方案只有相关性表格或故事性机制时不能通过。
- 广度审计区分确认性核心、必要边界、最小外部效度、可选扩展和明确排除项；新增模型、数据集或变量必须关联 claim、rival、threat 或外部效度，并有停止扩张规则。
- 当前 Proposal ID 完成五轮 `full-proposal-cycle`，每轮均重新检查深度、广度、新颖性、机制、识别和完整论文证据包；旧 Proposal 轮次、重复搜索和措辞润色不计数。
- `Proposal decision`、`Novelty status`、`Empirical status` 与 `Execution readiness` 相互独立；`Empirical status: not-run` 不导致 Proposal 失败。
- threat register 将问题分为 `proposal-fatal`、`empirical-dependency` 和 `paper-stage`，只允许未解决的后两类随通过方案向下游交接。
- GitHub artifact 只用于实现、许可和资源可行性核验，不以 star、README 或代码存在证明新颖性与正确性。
- 理论预测能够区分竞争解释，并逐项映射到可失败实验。
- 协议在主结果出现前冻结；Pilot 不通过时不得进入主实验。
- 失败 run 和协议偏离被保留；结论允许 supported、refuted、mixed 或 inconclusive。

## 交付

- 默认使用简体中文，并区分 `reported`、`derived`、`inference` 和 `proposal`。
- 用户交付物只放在 `outputs/`；内部状态、证据、运行记录与来源放在 `.research/`。

## 路由与精读回归场景

- 用户只要某问题的近期论文：按问题检索并给出处，不初始化长期状态机、不生成Proposal和实验设计。
- 用户要求精读某篇理论论文：核查命题、证明和假设；不要求其提供GPU、数据split或模型训练消融。
- 用户要求精读一篇方法论文，但只有摘要与局部正文：说明读到哪里、哪些关键证据未取得；不以PDF已下载或达到篇数宣布深入精读完成。
- 两篇论文使用同名指标却有不同公式：先比较定义、条件和聚合单位；不能直接宣称结论矛盾。卡片应给出可复核解释及来源定位。
- 核心结论依赖一幅图，但文本提取缺失图例：实际查看原图再判断；不能把解析错误写成论文错误。
- 搜索反复只返回同批摘要，关键附录仍缺失：切换获取渠道或保持待补读；不以重复查询累计饱和轮次。
- 原请求涉及多个学习对象，但候选只涉及其中一种：继续保留其他必要分支的证据问题，不能把候选近邻调研称为整个领域已深入。
- 报告每句都有引用，但来源只支持事实而不支持机制推断：回到原文审核推断并收缩主张，不能因结构审计通过宣布科学正确。
- 将两个不同领域的项目先后交给同一Agent：来源、查询、材料和验证方法均从各自scope产生，不互相继承；用户给定的来源偏好不自动改成所有项目的白名单。
- 用户要求优化Agent或转换报告格式：完成工程/编辑任务，不因为仓库含research目录就开启科研迭代。
- 用户要求借鉴科研Agent流程以提高本Agent自主性：直接改进通用能力与开发记录，不创建“科研Agent流程”研究课题；只在明确要求研究该科学对象时创建课题。
- 用户授权完成某一调研阶段：持续执行取证、阅读、复核与补检，不把输出下一步清单当作阶段完成；阶段证据不足时保留原因并继续可执行工作。
- 中断发生在外部任务已启动、结果尚未登记时：先核对原任务身份与产物，不直接再次启动；无法核对时明确未知状态，不伪装执行失败。
- 关键来源被修正或发现反证：定位受影响结论并回退复核，保留原记录；不能只在最后追加免责声明而保留旧主张。
- 资源预算由调用参数登记、没有遥测时：报告登记用量及其来源，不宣称已实时监控或自动停止任务。
- 已有项目只要求继续研究设计：先verify-log/status恢复；不覆盖init、不输出不存在的阶段名、不将设计迭代当实验授权。

- 内部report索引有效但用户交付报告为空、缺失或更新后状态未同步：调研审计应指出交付问题，不能只检查索引后通过。
- 经验系统理论阶段只调用机制审查；形式理论阶段才增加证明审查。理论回退不抹去已有实验历史，各状态按受影响范围单独处理。
- 用户要查看未通过的实验方案：交付明确标记draft/pending的蓝图；协议冻结不代表可部署或获得执行授权。

- 来源文件丢失或符号链接换向：旧结果不可复用并显示原因；放弃任务时保留记录、撤销旧凭证，取消登记不冒充停止外部进程。
- 队列依赖超过千层或大量共享祖先：校验不递归溢出，同次检查不反复读取同一来源；损坏记录和循环依赖拒绝写回。
- 项目处于待迁移状态或事件链损坏：队列不绕过控制平面继续变更；写盘失败保持原记录，临时文件不覆盖其他文件。


## 调研深度与解读清晰度验收

- 长期调研已交付报告，用户后来指出一处误读：恢复原问题ID，重新打开问题，核对来源并修正依赖结论；不重新初始化项目，不自动创建Proposal。
- 只有排版或单分支补检：分别更新报告日期或该分支检索日期，不将全领域检索截止日期改成今天。
- 已回答问题的来源换版：保留旧版本依据，复核受影响的claim、比较和报告；尚未复核的结论降级，不能只添加末尾免责声明。
- 长期调研没有新的取证触发：保存下一更新条件，不虚构新轮次、证据或后台监测；实际定时运行必须存在调用宿主的调度器。
- 用户同时指出综述不全面、论文浅：分别诊断必要分支和核心理解缺口，实际补检/补读后给出旧判断到新判断的变化；不能只修改流程或重排报告。
- 所有取证任务均已完成，但一次任务仅证实附录不可访问：科学问题保持开放，不能根据队列清空宣布调研饱和。
- 多分支问题只有一个分支深入：交付应说明分支差异并优先补关键缺口，不能用总篇数宣布全领域深入；也不强制所有分支相同篇数。
- 论文卡只有动机、方法名和一句局限：补足方法的具体输入、关键步骤、输出与对照依据；未理解时回原文，不能仅增加标题或篇幅。
- 方法已正确理解但段落混杂公式、结果和批评：先讲直观机制与例子，再解释公式与证据，保留必要细节且不改变结论强度。
- 某论文与当前候选无直接关系但回答原问题的重要分支：先完整解释其贡献，不因其无法支持候选而省略或排除。
- 理论论文没有训练步骤或消融实验：使用命题、证明依赖、边界例与反例检查，不强填算法实验模板。
- 补读纠正旧解释：当前论文卡、账本、报告和范围摘要应一致，旧说法仅作为有日期的修正历史保留。

- 一个分类列出多篇核心论文，但只有共同背景和方法名：每篇形成可独立阅读的说明，再作跨文比较；不能把术语表或分类表当作方法解释。
- 缩写都已展开，但读者仍不知其作用：用一个具体输入说明概念、组件和数据的角色，不以全称齐全验收。
- 论文介绍直接从动机跳到公式：补齐同一例子上的中间处理、信息来源及训练/使用路径，说明相对基线在哪一步变化；未理解则返回原文。
- 报告详细罗列某论文局限，却没有说明它带来什么：先还原作者贡献及关键证据，再解释适用条件和对课题的启发，不能把每篇只当作候选的新颖性障碍。
- 用户同时要求改报告与改Agent：交付具体报告修复及通用Skill/模板改动，通用文件不包含该课题论文、查询词或默认环境；不能只改其中一项。
- 说明性例子偷偷使用未来答案或环境真值，而原方法没有该输入：修正例子并复核依赖结论，不以例子流畅通过理解验收。
- 中文加粗或脚注在用户阅读器中裸露：用普通链接和无歧义标点修复渲染；排版通过不算新增证据或完整精读。

以上是宿主实际阅读任务的语义验收场景。静态模板校验与代码测试不能证明这些场景已经通过，也不能把旧论文卡自动升级为深入精读。

- 用户要求逐篇包含动机、方法、结果和分析：每篇核心论文分别给出有原文依据的内容；方法再详细也不能抵消结果缺失，添加四个标签不是通过依据。
- 持续调研只做旧报告润色或只收集新论文：同时检查已有理解缺口与新证据变化，执行必要补读/补检，并把有效证据写回同一报告；未部署调度器不承诺后台运行。
- 消融分数高于主表但来自不同子集或训练阶段：就地解释条件差异，不把二者拼成同一条性能提升链。

- 用户所说结果指实验结论、分析指整篇启发：正文以有证据的认识为主，数值用于必要支撑，详细对照保留内部；启发说明可迁移思路与边界，不再次堆分数或只写局限。

- 用户连续指出多个章节浅显，随后要求修复整篇：检查全部核心解释、章节综合和首尾问题一致性，修复同类缺口；不能只改点名章节或仅添加统一标签。
- 旧候选和已撤回限制仍影响结尾：当前报告回到原问题与有效约束，历史记录保留出处；不让候选排除必要文献，也不手改机器状态冒充科学门禁。

- 用户要求简化结果标签：改为“结论”，保留实验/理论的证据及条件，不把简化标签理解为删减分析。
- 构造例子被误解成真实训练数据：补任务背景与信息条件，自然融入方法；区分构造与来源案例，不使用“教学样本链”等内部术语。
- Markdown导出PDF：正文顺序和公式语义保持一致；数学字体实际加载，分式、上下标、乘积与行内基线无重叠；解析错误或字体缺失时拒绝覆盖原文件。

- 原文图文解读：截取后核对完整坐标/图例/子面板与图注，保留来源版本和裁切记录；正文解释图意及边界，不能只贴图、重画数据或裁掉不利对照。
- 图像在Markdown可见但导出后裁切/图注分离：实际检查PDF并修复同页布局及宽高比；图片加载通过不能代替视觉验收。

### 图文综述与证据迭代验收

- 用户希望流程图：优先截原文主要方法图；复合图仅留方法面板须标明，正文不靠实验截图代替解释。原文实验仍应核对。
- 主实验给定oracle信息、另有检索行：区分两种设置，不把前者写成自主获取信息。
- 首次执行下降而重试后改善：结论保留两种终点及成本，不宣布能力全面提高。
- 筛选同时改变分母或总权重：解释公式和竞争因素，不将消融自动等同于机制因果证明。
- 连续两轮同一待补读动作：实际执行或注明具体阻碍；纯编辑不刷新检索和取证日期。

### 全面调研与持续加深验收

- 用户要求“所有相关工作”：明确范围与截止日期，实际检查问题检索、双向引文及近期来源；不承诺绝对穷尽，不以数量验收。
- 连续批次集中同一分支：检查其他必要分支的阅读欠账，下一批选择仍可取证的重要薄弱分支，不让候选决定全部优先级。
- 候选论文持续增加而近邻未读：减少重复收集，先解决影响结论的阅读依赖。
- 新论文不能放入旧分类：回查范围与分类是否遗漏，不为了沿用报告标题排除相关工作。
- 一批调研完成：能指出来源定位和认识变化；仅新增介绍或改善排版不登记为科学进度。

### 调研终止判断验收

- 已达用户轮数但中心近邻未读：保存未完成快照，不标为范围内完成。
- 连续查询无新标题但必要分支仍薄弱：切换发现路径或补读，不能按无新结果终止。
- 收尾发现反证改变适用条件：重开受影响问题及综合依赖，其他有效证据不清空。
- 中心证据因访问限制无法核验：记录替代尝试与受影响主张，受限暂停不冒充完成。
- 仍有科学开放问题但关键文献已表明无法判定：解释证据边界，可在其余条件满足时完成当前综述，不自动执行实验。
- 所有质量条件已有可定位证据且收尾复核无实质缺口：交付范围内完成快照，不为凑轮数继续；保存重启触发条件。
- 强分支充分、弱分支仅有摘要：不允许总评分抵消遗漏，不为通过而静默缩小范围。
