# 证据综合

目标是回答领域已知道什么、凭什么知道、还不能判断什么。以用户原问题组织综合，再讨论候选方向；单个候选的近邻审计不能替代整个课题调研。

## 按问题而非论文数量组织

1. 恢复用户问题、必要分支及范围外事项，检查检索记录和逐篇实际阅读深度。分支由问题需要决定，不套固定数量或模型/数据类别；必要分支不能因为当前候选不涉及而被删除。
2. 对每个必要分支梳理定义、代表方法、前序与后续关系、最强支持和反向证据。关键结论只有摘要支持时，返回全文；背景摘要只承担定位。
3. 先形成领域级分类、发展脉络和证据判断，再选核心论文作深入解释。已详细分析的局部分支与仅有背景覆盖的分支分开陈述，不能平均成“整体深入”。

## 在共同问题下比较证据

在现有 `.research/review/evidence.md` 中维护主张级比较：问题、变量定义、输入及可见信息、处理差异、学习/推理位置、目标或命题、关键对照、预算、结果范围和竞争解释。同一术语可能指不同构念，相反数字也未必互相矛盾；缺失项回到原文核查。

关键结论使用 claim ID，标记 reported、derived、inference 或 proposal，连接来源及章节/公式/表图。分别说明原文的支持强度与综合推断的不确定性，不给没有依据的精确置信分。

- 只有任务、数据、split、指标、协议和资源足够兼容时比较数值；其他情况解释设置差异，不拼跨论文排行榜。
- 有分歧时区分定义差异、实验条件差异、识别不足和同条件下真实冲突。保留未解决冲突及区分解释所需的证据，不用多数票裁决。
- 方法谱系应说明后续工作改变了哪个假设、监督或验证方式，不能只按年份列标题。
- 研究方向须阅读[空白验证](references/research-gap-validation.md)与[方向构建](references/research-direction-construction.md)。先核对最近邻和反向检索，再提出科学问题、决定性检验与负结果价值；“某篇未测”不是领域空白。

## 先完成证据判断，再写用户报告

使用[综合模板](assets/synthesis-output.md)，按“直接回答 → 领域解释 → 核心论文 → 未解问题”展开。核心论文沿 `paper-analysis` 的“背景与动机—方法—结论—启发”结构，保留例子、关键机制和证据边界；不能为了排版一致将深入分析压回三句摘要。

内部账本承担完整 claim、来源与修正追踪；用户报告用连贯解释和就近引用呈现结论，不混排机器字段、查询日志或整张审计表。必要术语首次解释，实验设置、结果与批评分段。实际课题启示放在领域结论之后，不把每篇解读变成 Proposal 辩护。

## 分类与逐篇说明的两层组织

分类层先说明共同问题、必要术语及路线差异；论文层让每篇核心来源独立解释自己的背景、输入输出、方法或证明链、关键证据与贡献。若一段并列多个方法名而无法逐一走通，拆为独立说明后再比较，不能用分类表替代解读。辅助来源可以简述，但不得承担未精读的中心机制结论。

当用户指出阅读困难，沿`paper-analysis`的[解释修复](../paper-analysis/references/explanation-repair.md)检查理解依赖。既检查分支是否遗漏，也检查分支内的单篇是否跳步。对原文已理解的内容补写直觉和例子，对自己不明白的内容实际补读；先完成作者贡献解释，再联系候选方案。

## 交付前核验与补检

课题综述首次综合后、恢复长期调研、发现新证据，以及用户指出“不全面”“解读浅”时，执行[调研迭代](references/review-iteration.md)。同时检查问题覆盖与论文理解；依据缺口回到检索或原文，不把所有反馈都处理成重写报告。长期调研独立于正式研究设计；一次报告交付是有日期的认识快照，已回答问题仍可重新打开。

反向检查每个中心结论及会改变方向的数字：回到原文，检查其是否支持原子事实，以及组合后的事实能否推出当前解释。其他非核心结论按影响抽查，记录范围。单次自我复核不称独立审计，结构脚本通过不称科学正确。

逐个必要分支判断：问题是否有可定位答案，直接近邻是否达到所需阅读深度，最强替代解释是否已处理，仍缺什么证据。下一轮优先处理最可能改变领域判断的缺口；没有新证据的扩写不计进展。

停止条件是用户问题在明确范围内得到充分回答，或已明确资源/访问限制下无法解决的事项；不能因篇数达标、无新标题或报告写完而宣布饱和。普通调研不强制完整 Proposal 门禁；正式方案另按 `research-proposal` 的范围饱和和新颖性要求执行，状态只能有界地记为 exploratory、provisional 或 audited。

新证据改变定义、比较关系或结论强度时，同步更新论文卡、证据账本、报告和当前范围摘要；旧解释移入有日期的修正记录，避免多个“当前结论”并存。正式项目的科学回退仍通过 `researchctl.py` 登记。材料不足时交付明确标记缺口的阶段报告，不把预期深度写成已完成事实。

## 用户报告的表达与导出

正文优先使用简洁的“结论”标签，证据类型在句中解释；例子带上场景和信息条件，融入方法，不把内部“样本链”验收术语搬给读者。检查共同背景、逐篇解释与跨文综合各自的作用，删去重复导语，保留理解所需细节。

用户要求PDF时，按[文档导出](references/document-export.md)直接转换已定稿Markdown。保持原文与公式，不另写精简版，不默认增加封面、目录或章节强制分页。排版验证与科学证据验收分别进行。
