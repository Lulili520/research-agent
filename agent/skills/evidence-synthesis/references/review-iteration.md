# 由证据缺口驱动的调研迭代

适用于课题综述及其修订，不替代正式 Proposal 门禁。执行者是当前宿主 Agent；任务队列负责恢复和版本检查，不自动判断科学质量。

## 长期维护与恢复

用户要求持续调研时，沿用同一课题、问题标识和报告，不每轮重建项目或另开综述。先读 `search-log.md` 的当前维护摘要与开放问题，再按受影响范围读取论文卡、证据账本和报告。已初始化项目同时核验事件链、恢复机器状态及任务健康；只有文献材料的项目不因此被迫进入正式研究状态机。

当前维护摘要记录：用户问题及范围、最近实际检索日期、最近证据复核日期、当前报告日期、开放/受阻问题、最近结论修正、下一可执行动作及触发条件。三个日期分开：编辑报告不刷新检索截止日期；局部补检不刷新整个领域的覆盖日期。

问题保持稳定ID，在原问题队列中区分 `open`（待取证）、`answered`（当前范围有答案）、`blocked`（有具体阻碍）和 `out-of-scope`（有排除理由）。这些是文献问题的人工摘要，不是科研阶段或任务执行状态。重新打开问题时回到 `open` 并留下日期、触发证据和旧答案；不能因为一次读取任务完成就改成 `answered`。

恢复后的触发来源包括用户反馈、未闭合关键问题、论文修订/撤回或新近邻、来源文件变化、跨文冲突，以及按课题时效性约定的更新窗口。优先修正中心事实错误，再处理会改变答案的缺口；每轮重新检查必要分支，避免长期只追逐一个候选。即便没有新论文，已有材料的误读或薄弱证据也能触发迭代。

没有输入变化、开放问题或到期更新需求时，保留当前版本并说明何时再检查；不为凑轮数重复检索。存在可执行的必要任务时连续推进，不逐篇等待用户催促。真正中断时记录最后完成动作、未完成任务和下一动作，恢复后先核对产物，避免从头重读或重复提交。

## 修正如何传递

发现错误先定位受影响的来源版本、claim ID、问题ID及报告段落。证据账本保留“旧判断—修正判断—依据—影响范围”，当前卡片与报告只呈现有效解释；失效主张在尚未完成复核时明确降级或撤回，不能一边保留确定性结论一边只在末尾加免责声明。

再沿已登记依赖检查下游：其他论文比较、领域分类及已经存在的方案或协议。只复核受影响部分，不自动重跑整个研究；若影响正式阶段判断，交给 `researchctl.py` 登记决策或回退。报告需要更新时先完成证据综合和中心结论回查，再写当前版本；用有日期的修正记录保存历史，不复制整套相互竞争的“最终报告”。

每轮同时检查知识覆盖、方法理解、证据支持和表达清晰度。分别说明修复了什么以及剩余什么，不将四者合成为篇数、长度或自评分。长期维护可以收缩或推翻旧结论，质量改善不要求每轮都新增论文或得到更乐观结论。

## 一轮怎样执行

1. **诊断当前回答**：恢复原问题与现有报告，逐个必要分支检查代表路线、直接近邻、反向证据和实际阅读深度。另查核心论文是否能解释输入到输出、关键机制、决定性对照及结论边界。已有标题不能算覆盖，已有卡片不能算读懂。
2. **选择取证动作**：优先修复会改变中心结论的错误或空白，再补薄弱的必要分支。缺方法谱系就扩展术语和引文链；缺理解就重读方法、公式或前序依赖；缺证据就核查对照、消融、附录和图像；仅表述不清才直接改写。每项动作预先说明要回答什么及怎样判定回答到位。
3. **实际执行并核验**：检索、获取、阅读和比对结果；明确新增证据及定位。出现相反结果、来源冲突或新必要分支时更新问题队列。一个问题可跨多篇论文，一篇论文也可回答多个问题，不按篇数计算进度。
4. **局部综合并回查**：写清旧判断、新判断和改变原因；未改变也说明新证据排除了哪种疑问。回原文检验新结论，同步更新当前论文卡、证据账本和用户报告，再选择下一缺口。

每轮结束在现有 `review/search-log.md` 保存简短记录：问题、动作/来源版本、实际读到的位置、新增或修正的认识、剩余缺口、下一动作及继续/交付理由。纯排版标为编辑；只搜索到相同摘要标为未取得所需证据，不累计科学进展。

## 恢复与执行衔接

普通调研使用上述 Markdown 记录即可，不为此初始化长期状态机。已初始化项目复用 `agent/runtime/research/taskqueue.py`：

- `add`：问题写入 `--question`，理解或证据要求写入 `--acceptance`；`--inputs` 绑定实际来源，后续综合通过 `--depends` 依赖已登记的阅读任务。
- `claim` 后由宿主实际调用工具、阅读并产出论文卡或证据记录；`finish` 的 `--note` 说明回答、结论变化和剩余缺口，`--outputs` 指向真实产物。
- `list` 检查 `usable/ready/reasons`。来源修改、产物丢失或上游重跑时重新核验；先核对已有执行再 `reconcile`，保留旧解释及修正原因。

任务完成仅表示这一项取证产物已登记。把“仍未知”准确定位到来源限制也可完成一次访问任务，但对应科学问题仍开放；不能通过关闭任务清空证据缺口。改变阶段或科学决策仍由 `researchctl.py` 登记。

## 迭代约定与终止判断

开始或恢复深入调研时，在现有search-log当前摘要登记：本次范围与截止日期、必要问题ID、中心结论、尚欠证据、当前批次目标、已知资源边界，以及交付与重启条件。已有约定沿用；常规取证选择由Agent决定，不为填字段反复询问用户。未约定的时限或预算不虚构为授权，不默认启动无限循环。

### 三种不同的结束

- **一轮结束**：所选证据问题已实际取证、理解核验并综合回查，更新受影响结论和下一动作。若取证失败，记录尝试与阻碍，可以结束执行批次，但科学问题仍为open或blocked。一次轮次围绕证据问题组织，不以固定篇数、一次工具调用或一次报告编辑计数。
- **范围内完成**：下述质量条件全部满足，交付有日期的报告快照，停止本次主动扩展。仍可列出证据已表明无法由现有文献决定的科学开放问题。
- **受限暂停或用户停止**：达到已约定预算/时限、必要材料不可访问且已尝试合理替代路径、后续需要新增授权，或用户要求停止。先保存进度、受影响结论与恢复条件；质量条件未满足就标明未完成，不能把资源耗尽计作范围饱和。正常进度汇报和产物检查点不等于停止执行。

以上是人类可读的调研交付判断，不新增或手改researchctl机器阶段，也不等同于正式Proposal通过。

### 范围内完成的必要条件

1. **范围有答案**：每个必要问题都有来源支持的回答，或有证据支持的“现有材料不能判定”；没有被静默遗漏的必要分支。因当前执行者未读懂而未知，与领域尚无答案严格区分。
2. **发现路径经过检查**：实际检查问题/别名检索、关键前后引文及近期相关来源；记录日期、范围和访问限制。已发现、可能改变中心回答的直接近邻都有处理结论，不能仍停在待读标题。来源不可访问且影响中心判断时进入受限暂停，而非完成。
3. **中心机制可复核**：承载中心判断的来源，已读通所需方法、关键公式、决定性证据及相关附录；能解释条件、对照与允许结论。与本次主张无关的附录可以未读，但须说明不影响哪些判断；不要求所有背景文献同等精读。
4. **综合经受反向检查**：主动寻找遗漏路线、更简单解释及反证，核查表面冲突是否来自定义、信息、预算或终点差异。不可消解的冲突可保留，但其性质与影响须被准确限定，不能拿平均结论遮盖。
5. **收尾复核没有新的实质缺口**：在当前答案形成后，完成针对薄弱分支的补检与中心结论原文回查；记录实际来源及为何不足以改变当前答案。出现新必要分支、直接近邻覆盖、方法误读、结论方向或适用条件变化，重新打开受影响问题，补证后再做收尾复核。只重复同一查询或重写相同结论无效。
6. **剩余工作与本次回答分离**：所有未完成项都能说明为何不影响当前结论，或需要现有文献以外的新实验/新材料才能回答。仍有可访问且可能实质改变当前回答的取证任务时继续；不能仅凭主观“收益不大”停止。
7. **交付可追溯**：论文卡、证据账本、报告及当前摘要一致，中心主张有原文定位，实际阅读深度如实标注，结构审计通过。结构通过只是必要的工程检查，不证明科学正确，也不能自称独立审计。

这些条件按每个必要问题判定，不能通过加权总分让强分支抵消弱分支。不能为了提前通过而事后缩小范围或降低中心主张；合理范围调整须记录理由、原范围未回答事项及对用户目标的影响，实质改变用户目标时需要澄清。

### 轮数、稳定与无进展

不将普通综述设为“固定若干轮即完成”。先按问题安排有限批次，批次后依据以上条件决定继续、交付或暂停；用户给定轮数时按其作为执行边界，到轮数但质量不足仍交付未完成状态。正式Proposal的五轮及连续稳定要求不移植到普通调研。

“稳定”指针对薄弱点及反方解释的实际新检查没有改变当前答案，不是没有新论文或连续几轮没有改字。与当前答案等价的新工作需记录等价依据；无需为新增引用重做全部调研。实质变化只重开受影响分支和依赖，不清空已验证的其他分支。

连续无进展时诊断是术语/来源重复、理解欠账、访问阻碍还是问题本身无法由文献回答。可执行替代路径存在就切换方法；合理路径耗尽则说明受限或证据不足，不用空轮次维持“持续运行”，也不擅自开展实验补答案。

### 重新启动条件

出现影响中心判断的新论文/版本/撤回、发现误读或遗漏分支、原访问阻碍解除、用户扩展范围，或到达已约定更新窗口时，恢复受影响问题。记录触发证据、旧答案和新取证动作，不因单纯经过一段时间就宣布旧结论失效。

当前实现支持会话内连续执行和跨会话恢复，不能会话结束后自行醒来。定期自动更新需要实际部署的外部调度器与任务范围、资源边界；日期字段不是后台执行能力。“范围内完成”仅对当前问题、证据版本及截止日期成立，不是永久结题。

## 广度、深度与综合的循环调度

“所有相关工作”是持续降低遗漏的方向，不能作为可证明的绝对完成状态。先明确当前问题、时间范围、纳入与排除原则；维护随证据修订的问题地图。分类是可修改的分析工具，不是只接收现有类别论文的过滤器。发现无法归类但与原问题有关的工作时，检查是否缺少必要分支，不为保持目录整齐而排除。

### 先建立可追踪的问题地图

在现有 `review/search-log.md` 的当前摘要中，为每个必要分支保留稳定问题ID、要回答的问题、纳入边界、术语与别名、前序/代表/后续路线、实际阅读范围、最近取证日期、最强反向证据和下一动作。复用corpus、论文卡和evidence中的记录，不另建重复论文库；不默认把内部覆盖表放进用户报告。

以关系说明谱系：某工作继承了哪个假设，替换了哪个组件或监督，批评了哪种结论，与哪条路线形成竞争。综述与代表论文用于寻找入口，随后回到原始来源；没有被现有种子引用的新工作，还要通过独立的问题词与来源检索发现。

### 每轮选择什么工作

1. **先修中心错误**：身份、版本、方法或证据误读会影响当前结论时，优先回查并修正下游比较。
2. **再补遗漏与长期薄弱分支**：若必要分支只有摘要、缺少关键前序或近期近邻，安排实际补检和阅读。检查最近若干轮是否一直集中于同一分支；其他分支仍有可执行的重要缺口时，下一批应转向其中影响最大的缺口。不能仅以已有候选最相关为理由一直推迟。
3. **消化决定性阅读欠账**：已发现但未读的直接近邻、方法依赖和反向证据，优先于继续扩充相同路线的候选名单。已有核心理解欠账未处理时，缩小新论文收集规模；新近邻可能推翻结论时仍立即核读，不以固定篇数阻挡。
4. **完成跨文比较**：对当前分支比较共同问题、真正的方法差别、支持条件与解释冲突。综合暴露新的概念依赖或遗漏时返回检索，而非强行得出共同结论。
5. **回查报告与全局地图**：新增证据可能改变开篇分类、整章结论和末尾开放问题，不能只追加一篇介绍。每批记录认知变化，再选择下一项动作。

优先级用可解释理由表达：对中心答案的影响、当前证据欠缺程度、被遗漏风险及实际可访问性。不编造精确评分，不用容易取得PDF或热门程度替代相关性。一次批次可专注补读或综合，无需机械地每轮增加论文；一次阶段性交付前必须检查各必要分支是否被长期搁置。

### 如何判断真的加深了理解

一项核心阅读任务要回答一个具体问题，例如哪个假设支撑该机制、关键损失改变了什么、决定性对照排除了什么解释。按论文类型核查输入输出、方法图、必要公式、主要证据、反例和相关附录；实际读到哪里写到哪里。能给出标题、四段介绍或成功例子，不足以证明理解已经闭合。

每轮知识更新至少记录一种可核验变化：补出先前遗漏的路线、解释了之前不懂的机制、发现原结论的限制或反证、区分了看似相同的两种方法，或确认在新增证据下原判断仍成立并说明排除了什么疑问。纯语言、图文和排版改进单独记作编辑，不累计科学进度。

### 交付与下次恢复

沿用同一报告，交付时说明当前能回答什么、哪些分支仍薄弱、实际检索与阅读截止日期、最值得继续解决的问题。没有新标题只说明本次查询没有新发现；连续返回同样论文时，应检查术语、种子偏差和来源盲区，不自动判为范围饱和。既有核心近邻未读、中心冲突尚可取证时，不宣称范围内完成。

当前会话内按既有授权连续执行；跨会话由当前摘要恢复。跨日自动更新需要实际部署的外部调度器，并明确来源更新窗口、调用与资源边界；本规则本身不提供后台运行能力。普通综述不因此启动Proposal固定轮数门禁或实验。

## 整篇修复不能止于用户举出的段落

用户连续指出多节存在同类问题，或明确要求修复整份报告时，先将示例抽象为全篇检查项，再检查全部核心解释与综合段落。用户指出的段落是诊断入口，不是默认的修复边界。保留已经充分的内容，针对真实缺口改写或取证，不机械地把所有段落扩成同样长度。

逐篇检查动机是否具体、术语能否就地理解、方法能否从输入追踪到输出、实验结论是否有对照支撑、启发是否说明整篇贡献；按研究类型取舍。逐章检查共同问题、方法差异、条件与冲突，避免把独立论文卡串起来。全篇再检查开头问题、分类范围、结尾综合和开放问题是否一致，以及已撤回约束、旧候选、机器状态是否侵入当前用户报告。

先把作者的方法讲通，再讨论证据和限制；结果概括实验或证明支持的认识，必要数值与定位保留，详细算例可以交给内部证据材料。启发既说明可复用思路，也解释成立条件，不能被局限清单或对单个候选的批评替代。已有细致段落无需为格式统一删去关键机制。

交付前回查关键比较和结尾主张的来源依赖，同步当前维护摘要并保留修正历史。编辑、补读、新检索和科学判断改变分别记录；结构检查通过、解释单元齐全都不等于完成全文精读或领域饱和。

## 将证据变化传到全篇

开篇采用的分析维度必须用于后文比较。能力分类与训练机制可以交叉，但需明确学习对象、监督位置、标签来源及更新位置；不能把不同分类轴并排当作互斥能力，也不强制生成覆盖表。综合结论区分直接支持、条件性支持、存在冲突及尚未识别的解释，并从后两者选择下一项实际取证动作。

每轮分开记录科学取证和编辑：前者写来源位置、旧判断、新判断或排除的解释；后者写结构、术语、图片与排版变化。连续出现同一个“下一动作”时，应执行可访问的来源阅读或准确记录阻碍，不能以改写同一计划算作推进。用户要求整篇修复时，完成逐章检查，中心结论必须回查，保持充分的原有内容，不用增加论文数量替代修复。
