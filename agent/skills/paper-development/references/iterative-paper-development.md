# 论文多轮迭代

每轮必须读取上一轮正文、声明—证据表和审稿问题。只有新证据、新反例或新的论证压力产生实质判断时才计为迭代；改措辞、调格式和增加无关引用不计。

## 必需轮次

1. `contribution-architecture`：确定一个核心主张、必要子主张、读者、最近邻差异和完整故事边界；检查是否只是一组零散实验。
2. `evidence-stress-test`：逐项攻击因果识别、统计功效、强基线、公平预算、数据污染、外部效度和结果后选择；删除证据不支持的主张。
3. `theory-result-reconciliation`：比较预注册预测与实际结果，明确支持、反驳、混合和不确定部分；理论若变化必须版本化，不能倒填预测。
4. `artifact-and-reproducibility`：从干净环境重建核心表图，核验配置、随机种子、依赖、数据许可、资源和失败处理。
5. `independent-review`：按统一顶会标准的重要性、新颖性、深度、理论、正确性、实验充分性、泛化、复现、伦理和表达进行反方审稿，给出 `not-ready|major-revision|agent-review-cleared`。最后一项仅表示自动化内部审查通过，不替代外部专家判断。

`major-revision` 必须返回被指出的最早阶段。最后一轮仍改变核心主张、主要分析或关键表图时，继续迭代直至连续一轮无实质科学变化；这不是录用保证。

## 每轮记录

`paper/iterations.jsonl` 至少记录：轮次、输入版本、攻击问题、发现、删除/收缩/保留的声明、正文变化、所需新证据、决策和下一步。模拟审稿人与论文 Builder 的角色和产物分离，Reviewer 不继承“应该投稿”的结论。
