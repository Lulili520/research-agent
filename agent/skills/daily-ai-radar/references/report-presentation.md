# 每日论文精读表达与版式规范

## 阅读目标

默认读者有通用 AI 背景，但不了解具体 benchmark、模型缩写或机器人平台。报告应承担“首轮替代原文阅读”的功能：读完后能够复述论文为何出现、系统如何运行、各组件解决什么失败模式、实验怎样支持结论，以及哪些主张仍不可靠。

## 内容顺序

报告以逐篇精读为主体。每篇论文使用以下三个固定部分：

1. **研究动机**：从现实失败场景或直观矛盾切入，并解释理解论文必需的背景概念。
2. **方法介绍**：按输入、处理过程、输出和训练/评测信号讲清数据流；逐项解释设计对应的失败模式、为何可能有效以及与简单方案的差别；把 3–5 条核心实验作为内部小节，每条包含比较对象、数字、定位和它支持的具体主张。
3. **总结归纳**：分别说明核心贡献、最可信证据、替代解释与外推边界；再给出与论文证据相连的科研启发、可证伪问题和至少一个可执行实验设计。启发只从当前论文出发，不自动映射个人研究主题或 Agent 项目。

## 通俗性要求

- 不直接翻译摘要。先说明“为什么这是个问题”，再说论文名称和术语。
- 一句话尽量只表达一个因果关系；段落优先控制在 2–4 句。
- 缩写首次出现时解释其作用，而不只是展开英文全称。
- 每篇先列出理解全文必需的 2–4 个背景概念。解释“它在系统里做什么”以及与相邻概念的区别；不得只给英文全称或同义反复。
- Controller、Worker、backbone、head、Judge、reward、embodiment、benchmark 等词不能假定读者天然理解。只有确实影响论文理解的概念才进入概念卡。
- 对 `rho`、成功率、分数等数字说明它回答了什么问题；避免数字堆叠。
- 读者若必须回原文才能知道组件如何交互、监督信号来自哪里或实验比较了什么，则精读深度不合格。
- “显著”“证明”“通用”等强词只有在论文设计和统计证据支持时使用。
- Agent 判断使用“我的理解/应该怎样理解”，不能伪装成作者报告。

完成后做删除测试：删掉不影响读者理解或判断的背景、形容词、作者列表和重复结论。

## Markdown 与 PDF 版式

- 标题下只给日期、精读数量和预计阅读时间，不增加摘要目录。
- 论文编号为二级标题，三个固定部分为三级标题；只有方法内部的“核心实验”可以使用四级标题。
- 表格只用于三项以上的严格对照；普通论述使用短段落或列表。
- 每篇之间使用分隔线；不要连续出现超过两个信息密集表格。
- PDF 采用经裁剪的 ElegantPaper 风格：正文使用适合连续阅读的中文衬线字体，标题和导航信息使用无衬线字体；通过蓝色层级、细分隔线、booktabs 表格、稳定页眉页码和充分留白建立秩序。只借鉴其正文排版语言，不保留作者、单位、摘要、关键词、定理环境、期刊信息、参考文献样式等与晨报无关的论文模板元素。
- 每篇论文使用独立视觉区块；概念解释用浅灰蓝卡片，可信之处用浅绿色卡片，需要谨慎用浅橙色卡片，二者不可混成普通正文。
- PDF 生成后逐页查看；发现溢出、断行异常、链接过长或层级不清时必须调整后重渲染。
