# 从问题证据生成 Proposal

用于生成或实质修订方案。目标是形成可被检验的知识问题，再选择方法；不将暂定算法、可用数据或报告中的一个分类自动变成选题。用户明确指定研究方法时将其作为范围约束，但仍需说明该方法回应什么知识缺口。

## 先形成最小问题论证

在现有`proposal/initial-design.md`或候选记录中回答以下问题，不另开一套用户报告。已有答案有效时复用；欠缺证据时实际补检或核读，不用推测补齐。

- **现象与条件**：什么对象在什么条件下出现了什么差异、困难或理论障碍？给出来源位置、案例或推导，标明reported/derived/inference/proposal。一个可能发生的例子不证明现象已存在或普遍存在。
- **现有解释**：最接近的方法如何处理它，解释或证明依赖哪些条件？未做某项消融、未测某个数据集，不自动等于知识空白。
- **知识缺口与重要性**：哪一判断仍无法由现有证据作出？回答后会改变什么理论、测量、方法选择或系统设计？将科学后果与“增加一个模块”“涨点”分开。
- **分析单位与终点**：研究一次决策、一段过程、整个系统、证明对象还是总体分布？现象、主张和评价是否使用同一层级？列出原始材料和判定路径，不能只指定一个指标名。
- **竞争解释与区别**：保留最强、最简单的替代解释。说明哪种合法条件变化或检验结果会使解释产生不同预期；暂时无法区分时把它登记为识别缺口。

先用普通语言表述：**在〔条件〕下，〔对象〕出现〔有依据的现象/障碍〕；已有工作建立了〔已知〕，却尚不能区分〔未知〕。拟通过〔判定路径〕回答它，进而改变〔知识或决策〕。** 这只是帮助发现缺口的句式，不是必须逐字填满的模板。

信息不足时先交付有来源的候选问题与缺口，不提前命名新算法、承诺正结果或生成一份貌似完整的“已验证方案”。

## 比较知识问题，再决定方法

候选需要在知识主张、解释或决定性证据上有实质差别。对每个候选写短的Q/K/M/D/C及最强淘汰理由，按现有门禁保留候选竞争记录，不用同一算法的参数变体凑候选。

对已有方案做一次去掉方法名的检查：如果移除方法名后只能剩下“提升表现”，回到现象和知识缺口；若用户目标本身是工程优化，明确按工程问题处理，不强行包装科学新颖性。

选择必须有条件：为什么当前证据支持优先推进它，哪项新发现会改选其他候选？先选最能改变判断的取证任务，而非最容易生成漂亮方案的方向。广域调研继续保留其余必要分支。

## 按研究类型解释M与D

保留Q/K/M/D/C与机器字段名称，但填写适配的科学含义。`mechanism`是兼容键名，不要求每种研究都提出因果中介。

| 研究类型 | M：依据 | D：有区分力的验证 |
|---|---|---|
| 机制或实证研究 | 构念、竞争解释及可能的因果关系；观察性证据限定解释 | 可识别比较、操纵或替代解释检验；未识别因果时降低主张 |
| 算法或系统研究 | 设计依据、系统不变量、资源/误差模型 | 与强且公平的基线比较，测量对应能力、开销、失败条件；不强制因果中介分析 |
| 理论研究 | 明确假设、命题、非平凡推导与最近理论边界 | 证明义务、反例、紧性或假设必要性；无需为填模板添加GPU实验 |
| benchmark或测量研究 | 构念定义、测量效度和所暴露的能力缺口 | 标签/判定可核验性、效度、可靠性、污染与捷径检查；不强制发明新训练算法 |
| 复现或综合研究 | 值得核验的主张、外推条件或证据冲突 | 独立复核、证据质量与异质性分析；明确贡献定位，不能伪装成首次提出 |

若不同解释都预测“指标提高”，检验还不具体。写出处理、比较项、固定项、主要终点、合法性判定和允许结论；每个变量必须能改变一项解释。诊断干预不能任意制造不可执行的环境状态。

## 先定义判定条件，后定义预期结果

将下列两件事分开：

- **检验是否有效**：所需材料确实可取得，处理是否改变了目标因素，指标是否有区分空间，标签/证明义务是否可核验。Proposal说明可行路径和将采用的质量检查；实际检验结果留待授权后的试点。
- **哪种解释得到支持**：有效检验下，哪些结果支持、反驳或收缩主张；哪些结果只能判为精度不足或当前资源内无法判断。

不要求实验前已经观察到效应。若方法根本无法区分假设，是proposal-fatal；如果原则上可区分但实际方差、操纵质量或效应未知，登记为empirical-dependency并交接验证条件。

## 按缺口安排下一次取证

每次行动在既有迭代记录中写：哪个问题会影响决策、输入与实际来源、为何选择这个动作、预期如何改变判断、实际发现及下一动作。可在`next_action`写明对应验收项；不另建重复状态机。

优先修复会推翻中心主张的问题，然后处理关键依赖与可行材料，再扩展必要边界。成本相近时优先选择能区分最强竞争解释的动作。不知道信息增益或费用时用有理由的定性比较，不虚构精确收益评分。

预算与科学状态分开：沿用已有时间、工具调用与资源授权；没有额度时执行可交付的有限证据批次并记录范围，不默认无限循环。达到资源边界就交接暂停及恢复条件，不能转为pass；发现路径重复且无新线索时说明具体阻碍或更换路径，不能靠继续改写声称收敛。

## 从候选交接到审查

先将问题论证压成可读的方案，再展开必须的技术细节。独立审查输入包含范围、当前Q/K/M/D/C、原始证据、最强近邻和未解决威胁，不附Builder希望通过的结论。审查要求见[独立新颖性审查](proposal-novelty-audit.md)。当前缺口明显时先修复，不为提前获得一个评分浪费审查。

意见在原`proposal/audit.md`中按“意见ID—受影响主张—来源/反例—修正或异议依据—当前处置—复核者”闭合。作者可以反驳意见，但须给出可检查证据；意见提出者或独立审查者复核后才关闭影响通过的争议。同一模型换角色或多次给相同分数不证明独立性；不可获得独立审查时交付revise草案。

七项验收通过后停止当前Proposal迭代，保持四轴状态分离；理论、协议和执行只在用户目标允许的阶段推进。该流程由宿主执行，不是后台自主调度器。
