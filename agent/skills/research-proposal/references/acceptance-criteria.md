# Proposal 按证据验收

适用于正式研究方案；普通文献调研沿用其范围内完成条件。迭代次数不决定通过，不设固定最低轮数、连续稳定轮数或综合分数阈值。轮次只用于追踪证据变化。理论与实验协议的独立门禁仍按对应阶段契约执行。

## 七项必须同时成立的要求

| 要求 / criterion ID | 必须回答的具体问题 | 可接受的证据与不通过情形 |
|---|---|---|
| 问题具体且重要 / problem | 哪类对象，在什么条件下，出现什么可观察困难？现有解释缺在哪里，解决后改变什么认识或决策？ | 来源定位、真实案例或严格推导支持问题；明确对象、条件、分析单位、比较项和终点。仅“提升能力”“改善泛化”不通过；不要求实验前已有本地正结果。 |
| 知识贡献与近邻差异 / contribution | 相比最接近的工作，方法、效率、可靠性、适用范围、保证或经验认识有哪些实质改进？名称不同但功能等价的工作是否已覆盖它？ | 问题、机制、证据和科学后果逐项比较；明确继承与新增。独立问题检索、引文链、近期来源与反向检索都有实际记录。关键近邻未读、只换模型/模块/数据或只说“未见”均不能通过。 |
| 可检验的依据 / mechanism | 为什么该主张成立？什么条件会使它失败？替代解释、设计或理论关系预期什么？ | 按研究类型给出机制、设计依据、系统不变量、测量效度或理论命题及区分性检验。字段mechanism保持兼容，不要求所有研究做因果中介分析。 |
| 决定性检验 / identification | 哪个处理或对照会使竞争解释产生不同预期？测量是否对准主张？ | 材料—处理—比较—终点—判定的对应关系、混杂与泄漏检查、判定错误如何影响解释。只列消融名称或所有解释都预期同样涨点不通过；不能用额外预算冒充能力。 |
| 纸面可行性 / feasibility | 数据、环境、标签/判定、工具与资源是否有可信取得路径？ | 具体材料版本/选择规则、许可与访问证据、预算估算及替代路径；无可靠终点或资源根本不可得属于致命缺口。实际效果、方差和操纵成功可留待试点。 |
| 必要广度与结论边界 / scope | 最小论证需要哪些子问题和适用边界？正、负、混合或无法判定分别贡献什么？ | 确认性核心、必要外部效度、强基线、结果—贡献矩阵、排除理由与扩张停止条件。按主张组织，不靠增加实验数量或承诺所有任务涨点。 |
| 当前版本独立审查 / independent-review | 独立审查者是否尝试推翻最强主张？意见是否按证据解决？ | 审查对象、最强反例、意见处置及独立性说明；作者不能自签。未解决proposal-fatal阻止通过，后续实证未知有明确交接即可。 |

每项用“判断—证据定位—尚存威胁及影响”说明。不可用空标题、通用好评或其余六项的高分抵消一个致命缺口。机制研究不一定需要新算法，理论或测量贡献也可成立，但必须有非等价的知识增量。

七项是本Agent的设计，不是已被验证最优的统一学界标准；外部来源支持哪些原则、哪些不能照搬，见[外部质量依据](../../iterative-research/references/external-quality-sources.md)。生成阶段先走[问题到方案](problem-to-proposal.md)，不能只按验收标题倒填内容。

## 如何决定继续、通过、放弃或暂停

- **继续修订（revise）**：存在可执行的关键取证任务或未解决致命缺口。下一动作按缺口选择，可能是补读、反向检索、核查材料或重写机制，不能机械重跑全流程。
- **通过（pass）**：七项均有可追溯证据，致命缺口已解决，当前版本及证据通过独立审查；范围结论建立在关键近邻与反向检查上，不依赖连续无新论文次数。
- **放弃（reject）**：核心贡献已等价覆盖、问题不重要或不可判定等缺陷无法在保持中心目标时修复。保留依据，重新比较候选。
- **暂停**：访问、资源或用户执行边界使必要工作无法继续。保存当前revise/reject判断和恢复条件，不把暂停转成pass。

新证据改变Q/K/M/D/C、材料、最近邻或判定依据时，重新打开受影响要求，复核下游结论并更新当前版本的验收。没有变化且各项已满足时即可交付；无须补足轮数。没有新增标题仍可能需要精读或核对实现。

执行预算与科学验收分开。沿用用户的时间、调用和资源约束，批次结束保存证据、待解决问题和下一动作；耗尽预算不等于通过。没有新标题也可能仍需核对方法或证据；没有新问题且已满足要求时不重复执行。

## 机器验收记录

`proposal/acceptance.json` 记录最终审查，未通过的方案可以不生成通过记录，或保留decision/status为revise。不能为满足门禁伪造独立审查。

字段：`version: 1`、`proposal_id`、`author`、`reviewer`、`reviewed_at`（ISO日期/时间）、`independence_statement`、`decision`、`open_fatal_issues`、`snapshots`、`criteria`。

`criteria` 的键为上表七个英文ID，每项包含 `status`、具体 `rationale` 和非空 `evidence` 列表；每条证据为 `{"path": "proposal/proposal.md", "locator": "第3节，Q/K/M/D/C"}`。路径相对`.research/`，必须绑定到`snapshots`中的SHA256。除必要清单外，将支撑主张的论文卡、关键来源和可行性记录一并绑定；审查者判断清单是否足以覆盖主张。

必要快照：当前方案、范围、检索日志、覆盖结论、最近邻比较、深度广度审查、独立新颖性审查、候选/主张/竞争解释/威胁记录。精确路径以`agent/runtime/research/proposal_acceptance.py`的REQUIRED_EVIDENCE及layout映射为准。轮次登记与人类状态摘要不充当科学证据。

运行时检查七项通过、证据存在与哈希一致、当前Proposal ID、作者与审查者标识不同、致命问题清空。它不能验证文字判断是否正确，也不能凭不同标识证明审查真正独立。旧验收在任一绑定文件变化后失效；复核后重新出具验收，不直接替换旧哈希延续通过。

策略`proposal-evidence-v7`替代Proposal的固定轮数门禁。旧项目须显式迁移并重新验收；不因取消次数要求自动升级任何旧方案。

同题近邻不是拒绝理由；按[同问题改进原则](proposal-novelty-audit.md#相同问题上的更好方案也是贡献)审查拟改进及其证据，不要求中心问题全新。
