# 研究 Proposal

产出是实验前的科学论证及其证据边界。先确定值得回答的具体问题，再决定方法；不承诺正结果、执行授权或论文录用。使用当前课题的范围、来源与资源，不从其他课题继承配置。

## 恢复目标和证据

已有课题先恢复当前版本、原问题与开放缺口；已初始化项目按[运行时契约](../iterative-research/references/runtime-contract.md)核验事件链和状态，不重新初始化。用户只要求调研时交给检索、精读与综合流程，不自动展开Proposal。

读取[问题到方案](references/problem-to-proposal.md)，检查现象、已知解释、知识缺口、分析单位和判定路径是否已有来源。相同问题上的更好方法是有效贡献路径；发现近邻先分析其限制并建立强比较，不为避让而强行换问题。问题宽泛时补证或收紧；不能先命名算法，再寻找支持它的论文。顶会目标参考[统一质量标准](../iterative-research/references/top-tier-research-standard.md)及其外部依据，不按会场选更宽松标准。

## 缺什么，就执行相应任务

| 当前缺口 | 实际动作与交接 |
|---|---|
| 领域分支或近邻遗漏 | `scholarly-search`按问题、术语、引文链和近期来源补检；按[范围与语料规则](references/corpus-and-saturation.md)记录取舍，候选不得吞掉领域其他必要分支 |
| 方法或决定性证据未读懂 | `paper-analysis`回到全文、关键对照及相关附录，必要时只读核对官方实现；明确未读和未理解部分 |
| 现象和知识缺口混杂 | `evidence-synthesis`区分来源事实、解释、未知与缺失实验；按[问题到方案](references/problem-to-proposal.md)形成最小问题论证 |
| 候选选择或机制不明确 | 按[证据迭代](references/iterative-proposal-development.md)比较知识不同的候选，构建Q/K/M/D/C和区分性预测 |
| 新颖性或可行性不明确 | 按[新颖性审查](references/proposal-novelty-audit.md)反查等价工作；核验材料、判定和资源路径，不以仓库存在或自评分证明科学价值 |

正式研究默认纳入与精读预算分别为50–100及20–30篇，数量不替代覆盖与理解；偏离时按范围说明理由。按最可能改变判断的缺口选择下一任务，不设固定循环次数，也不靠重复查询声明饱和。

## 构建可检验的当前方案

每个保留候选写清Q（问题）、K（知识主张）、M（适配研究类型的依据）、D（决定性检验）、C（不同结果的科学后果）。使用[实验前科学契约](references/proposal-gate-contract.md)与[深度广度审查](references/proposal-depth-breadth-audit.md)，建立中心问题、必要子问题、最强近邻、竞争解释、确认性核心、必要边界和扩张停止条件。

M/D按机制、系统、理论、测量等研究类型解释；不强制所有方案做因果中介分析或发明新算法。形式研究再按[理论闭环](references/novelty-depth-theory-loop.md)准备命题与证明义务。先说明检验是否有效，再说明哪些结果支持何种结论；未执行实验不等于方案不成立。

威胁在原记录中分为`proposal-fatal|empirical-dependency|paper-stage`。致命缺口须解决；实际效应、试点操纵结果或后续Artifact保留为待验证项，不伪造结果。只换名称、模型或数据不足以建立贡献；复用已有组件也不自动否定实质知识增量。

## 审查、迭代与停止

按[七项证据验收](references/acceptance-criteria.md)分别判断问题、贡献、依据、识别、可行性、必要边界与独立审查。自动评分只辅助定位疑问，不能代替证据。Builder不得代签独立审查；按[意见闭合规则](references/problem-to-proposal.md#从候选交接到审查)记录反例、处理依据和复核。

- 关键缺口仍可取证：继续或回到最早受影响环节；每次保存认识变化和下一动作。
- 核心贡献被覆盖或无法形成可判定问题：重新比较候选或reject，不靠堆扩展维持原方案。
- 当前证据与独立审查满足要求：pass并交付，不补足轮数。
- 资源、访问或授权边界阻断：保存当前判断与恢复条件，暂停不算通过。

时间/调用/算力预算控制执行，科学要求决定验收。不得为填模板反复询问已明确的约束，也不得在未约定上限时默认无限执行。关键方案或证据改变，旧验收失效，需要复核；具体机器记录沿用现有契约，不手改控制状态。

## 交付

使用[Proposal模板](assets/proposal.md)和[深度广度模板](assets/depth-breadth.md)。内部保存当前`proposal.md`、候选、主张、威胁、审查及迭代记录，旧版归档；用户只读`outputs/02-验证后Proposal.md`及按需图文/PDF。

正文首先介绍当前方案：用普通语言说明研究对象、具体问题、拟做的处理或方法、比较方式和希望获得的知识，首次术语就地解释。结论先行是先概括方案内容，不是先列“保留问题／继续修订”等审查处置。简要边界随方案说明，详细四轴状态与门禁集中在后文，再按论证展开问题依据、主张与范围、最近邻差异、材料判定、检验和可能结果。研究时先查证问题，不等于报告必须先罗列背景。开头区分已确定的方案内容与待选择的收紧方向，不能把待检验假设写成实验结论。每个核心问题只在一个主章节完整解释；详细候选竞争、版本变化与补检顺序移至附录或内部记录，关键反证和未解决缺口仍在正文明确展示。关键流程图应说明信息流和证据链；设计示意不得冒充论文原图或已运行系统。机器要求的行首字段集中保留在内部proposal.md末尾，用户报告使用可读状态表；两份主张与状态一致，不要求逐字镜像。四轴状态、深度/广度及论文充分性如实展示；稳定文件名不代表已通过。

有证据变化时同步修正`outputs/01-文献调研总结.md`的受影响结论，按其已有结构保留领域综合与逐篇深入解读，不为修改方案重写整篇报告。只有验收成立才进入用户所需的后续理论/协议阶段，协议冻结也不授权实验。

纯结构修订按编辑任务处理：保留原证据与科学版本，归档旧稿，同步内部Proposal及按需PDF，检查交叉引用；不刷新检索日期、不计作科学迭代，不自动恢复已暂停的研究。

修改通用PDF样式或统一同一交付的排版时，按[导出同步规则](../evidence-synthesis/references/document-export.md#同一交付中的排版同步)核对范围内每份现有MD/PDF的字体与样式版本，逐文件导出、抽查并登记；不能只更新最后讨论的文件便宣称整套文档已同步。
