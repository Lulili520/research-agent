# 研究 Proposal

目标不是用论文数量装饰想法，而是建立足以推翻错误创新判断的证据地图，再形成有理论依据、可证伪且资源可行的 Proposal。默认输出简体中文，论文官方标题和标识符保留原文。

## 调研

1. 先冻结 topic 的问题边界、相邻概念、时间与 venue 范围、研究类型、资源限制以及可能推翻创新性的等价工作定义。
2. 阅读[语料与饱和规则](references/corpus-and-saturation.md)，调用 `scholarly-search` 建立候选池和去重后的纳入语料。正式 Proposal 纳入 50–100 篇身份已核验论文；不得为了达标纳入明显无关记录。
3. 语料必须覆盖奠基工作、方法谱系、最近两个完整发表周期的前沿工作、直接竞争者、相邻问题、负面或矛盾证据以及 benchmark/评测工作。通过关键词、同义词、前后向引文、作者后续工作和最近相关工作迭代检索。
4. 对所有纳入论文建立结构化最小卡片；从中选择 20–30 篇最接近 Proposal 的核心论文，使用 `paper-analysis` 完成全文精读。核心集合必须覆盖直接竞争者、最新强基线、潜在先例、关键矛盾证据和主要实验协议；关键事实和新颖性判断不得仅依赖摘要。
5. 每轮记录新增唯一论文、重复项、新增概念和未解决近邻。当连续两轮定向检索的新相关记录很少且不再改变方法分类、最近近邻或 Proposal 判断时，才可声明范围内趋于饱和。

## Proposal 构建与审计

1. 先用 `evidence-synthesis` 形成问题谱系、方法分类、失败模式、证据冲突和候选方向，不要先写 Proposal 再寻找支持性论文。
2. 正式 Proposal 必须阅读并执行[多轮 Proposal 推演流程](references/iterative-proposal-development.md)。多轮的含义是让候选依次经历不同目的的否定性检查，不是反复润色同一文本；每轮写入 `proposal/iterations.jsonl`，并维护 claim、rival 与 threat register。
3. 阅读[Proposal 新颖性审计](references/proposal-novelty-audit.md)，为每个候选寻找最可能推翻它的工作；逐项比较问题、机制、训练/推理设置、数据、指标、资源假设和贡献。
4. Proposal Builder 与 `adversarial-novelty-reviewer` 分离：前者不得替后者填写结论。反方审计器生成 `novelty-review.md`，明确等价工作判据、最强反例、撤回声明、未解决威胁、独立性说明和决策。
5. Proposal 必须包含：问题与重要性、精确研究问题、最近近邻差异、机制或理论依据、可区分预测、可反证条件、实验概览、预期贡献、负结果价值、风险与资源估算。每个关键主张应能回溯到 claim register 和至少一轮专门压力测试。
6. 新颖性分开评估问题、机制、方法实例、实验协议和证据贡献。只有关键差异具有科学后果时才能保留，不能把模块拼接、换数据集或尚未比较的涨点称为创新。
7. 输出前按[Proposal 模板](assets/proposal.md)完成内部 `proposal/proposal.md` 和 `proposal/audit.md`，再生成面向用户的 `outputs/01-文献调研总结.md`。该报告必须包含三层：对 50–100 篇纳入集合的领域级综合分析；对 20–30 篇实际全文核心论文逐篇撰写“研究动机—方法介绍—总结归纳”；详细解释仍存在的问题、证据不足原因、最近邻边界和可验证方式。不得用摘要改写、批量一句话列表或论文卡链接代替精读正文。可同步生成 `outputs/02-验证后Proposal.md` 草案，但必须分别展示“新颖性审计”和“理论可行性审计”状态；最后连续两轮稳定性检索、必需推演轮和反方审计未通过时，不能标为 `audited`。新颖性只能标为 `exploratory`、`provisional` 或 `audited`，并注明检索截止日期和未覆盖范围。

若清晰问题边界内不足 50 篇相关论文，正式 Proposal 门禁保持未通过：应扩大合理的相邻概念或把产物降级为探索性调研，不得用无关论文凑数。若纳入超过 100 篇仍未达到范围饱和，应收紧研究问题或继续在候选池筛选，不得把超过上限的未分层集合直接带入 Proposal。
