# 学术论文检索

## 从当前问题构造检索

1. 从用户请求或当前项目范围提取研究对象、知识问题、比较方法、结果与限制；展开同义词、旧术语和歧义词。不要从其他项目或测试材料继承查询、论文名单或数据假设。
2. 选择适合该领域的学术索引、正式会议和期刊。领域顶级来源、代表工作及近期直接近邻共同覆盖，不把固定会场列表当作所有学科的白名单，也不因预印本未发表而漏掉可能等价的新工作。
3. 先做问题导向发现，再沿代表工作的参考文献和后续引用扩展，最后针对具体知识主张反向补检。查询随证据修订，保留原因；不能只检索支持预设方案的用词。
4. 正式项目将具体范围、来源选择和查询存入 `.research/review/`；快速查找只记录完成回答所需的信息，不创建整套项目。查询表、论文名单和抓取结果不写入通用 `agent/`。

## 调研中的检索闭环

综述修订先按 `evidence-synthesis` 的[调研迭代](../evidence-synthesis/references/review-iteration.md)诊断缺口类型；方法没读懂时先补读，不重复广域检索。补检产出回交同一问题的综合，不另开脱离原问题的论文清单。

对深入课题调研，在现有 `search-log.md` 中维护问题队列：具体疑问、影响的领域判断、已有证据、缺少的原文/近邻、下一查询或补读动作、结果。优先处理会推翻中心判断的缺口；同时保留原问题各必要分支，不能让一个暂定候选吞掉整个领域调研。

问题队列按必要分支记录当前最强证据与最薄弱环节：只有背景摘要、已读重点章节和已闭合核心问题分别说明。分支的重要性由原问题决定，不由暂定 Proposal 决定；不要求所有分支同样篇数，但每个影响中心回答的分支都须达到其主张所需的深度。先维护当前摘要，再保留有日期的历史修正，不能靠追加日志留下过期完成标签。

补全相关工作时同时检查三条发现路径：独立的问题/术语检索、代表工作的前向与后向引文、近期正式来源与预印本更新。三条路径分别记录实际执行及访问限制，不能只沿同一组种子扩展；新工作超出现有分类时回交问题地图修订。已发现的决定性近邻尚未读时，缩小同路线的重复收集并优先交接补读。

种子论文只作入口。沿关键方法的前序来源和后续引用追踪，并检索竞争术语、相反结论、失败及更简单解释；必要依赖进入 `paper-analysis`。数据库不可访问时记录替代渠道和未覆盖的引文方向，不以关键词命中冒充完成引文追踪。

每轮写清“新增/修正了什么认识，哪个疑问仍未解决”。反复返回相同摘要而没有取得所需证据时，切换原始来源、查询或报告访问缺口；不能用重复搜索计进度。达到数量、没有新标题或报告已生成都不是深入调研的停止条件。任务所需关键问题有可定位答案、直接近邻达到所需阅读深度、冲突被解释或明确保留后，才交接综合；受限时交付范围明确的未完成结果。正式新颖性另遵循已有饱和门禁。

## 核验与交接

- 以 DOI、arXiv、官方 proceedings、期刊或 OpenReview 核验身份，同一工作的多个版本合并计数。分别记录实际阅读版本与正式发表身份，明确年份、track 和 paper type。
- CCF 分类仅在任务需要时核验，阅读[CCF 会议规则](references/ccf-venue-rules.md)；高影响力筛选按需读[影响力策略](references/impact-prioritization.md)。不由会场名推断单篇正确性。
- 保存日期、数据库、完整查询、过滤条件、访问限制、纳入理由、排除理由及版本关系。没有观察到的引擎返回数不填造。
- 搜索摘要只用于发现。元数据/摘要记录不能支撑细节效果、机制或新颖性结论；这类问题交给 `paper-analysis` 核读原文。
- 普通查询以回答问题为停止条件；正式 Proposal 按 `research-proposal` 的覆盖与饱和契约继续，数量预算不能替代关键近邻核验。

记录格式见[检索模板](assets/search-output.md)。默认输出与问题有关的发现和缺口；来源覆盖表仅在用户需要时提供。
