# 理论分析与实验探究的五轮完整迭代

五轮不是把理论、实验、资源和审查拆成五个阶段。每一轮都必须完整执行一次：

```text
理论构念与机制
  -> 竞争解释与反证
  -> 构念效度与因果识别
  -> 预测—实验映射
  -> 数据、统计与资源部署
  -> 对抗性整体审查
  -> 修订理论、协议和用户报告
```

上一轮修订后的全部产物是下一轮输入。至少连续执行五轮；第五轮仍发生理论主张、主要预测、处理、主要终点、纳排规则、统计判定或资源可行性的实质变化时，不得宣称完成，必须继续完整迭代，直到最后一轮 `theory_changed=false` 且 `protocol_changed=false`。

## 每轮必查内容

1. 理论：构念、假设、适用域、机制链是否明确，是否存在循环论证或隐藏自由度。
2. 反证：主机制与至少一个竞争解释是否给出不同的可观察预测；每条路径能否被删除。
3. 识别：处理能否独立操纵，代理指标是否有效，混杂、泄漏和处理后选择是否受控。
4. 实验：全部核心预测是否映射到可失败的实验；主要和探索性分析是否分开。
5. 资源：数据版本、运行量、模型、CPU/GPU/RAM/磁盘、人工角色、工时、日历时间和授权是否具体可行。
6. 论文完整性：正、部分、负和不确定结果分别能形成什么有边界结论；是否足以支撑论文而非零散实验。

## 迭代记录

`theory/iterations.jsonl` 每行代表一轮完整循环，至少包含：

- `iteration_id` 与从 1 开始连续的 `round`；
- 固定 `cycle_type=full-theory-experiment-cycle`；
- `question`、`inputs`、`finding`、`decision`；
- `theory_review`、`rival_review`、`identification_review`、`experiment_review`、`resource_review`、`paper_review`；
- `theory_changed`、`protocol_changed`、`change_summary`、`unresolved`、`next_action`。

每个 review 字段必须记录本轮实际检查结论，不能写 `pass` 或“同上”代替。五轮记录不得预先一次性复制生成；每轮必须读取上一轮修改后的产物再得出结论。

如果理论变化，重新审查全部预测；如果处理、主要终点、排除、样本量或分析变化，协议必须升版。实验结果不能倒填为事先预测，只能触发带日期的新理论版本和新一轮完整迭代。
