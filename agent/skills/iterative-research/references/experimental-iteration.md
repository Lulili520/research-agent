# 实验迭代规则

## 协议

`experiments/protocol.md` 冻结研究问题、声明、假设、实验单元、自变量、因变量、控制变量、混杂因素、数据划分、污染检查、基线、指标、重复、随机性、统计分析、异常处理、资源预算和停止条件。每项核心声明必须关联至少一个可能反驳它的实验。

协议为机器审计保留 `Claims:`、`Independent variables:`、`Dependent variables:`、`Controls:`、`Baselines:`、`Metrics:`、`Randomness:`、`Analysis:` 和 `Stopping rules:` 标签；正文仍可使用中文。

协议修订保留版本、日期、触发证据和对既有结果的影响。看到主结果后新增的指标、子群、排除规则或假设一律标记为探索性，不能冒充预先设定的确认性检验。

## 试点

试点只验证可运行性、测量有效性、方差、成本和日志充分性。试点数据默认不并入主实验。出现任务天花板/地板、验证器不可靠、基线错误、数据泄漏、运行不可复现或成本超限时，返回协议阶段。

## 执行

每次运行分配稳定 run ID，保存代码提交/快照、配置、环境、输入身份、随机种子、开始结束时间、资源消耗、原始输出、处理脚本和退出状态。失败运行也进入 registry，不得静默删除。

先执行能最大化区分竞争解释的信息性实验，再扩展规模。比较结果前检查任务、数据、划分、指标、预算和实现是否兼容；报告效应量、不确定性和实际意义，不以单次最佳值或显著性代替证据。

## 诊断与稳健性

根据研究类型选择消融、替代指标、多随机种子、数据/模型/预算变化、反例、分布外测试、错误分类、敏感性分析和独立复现。诊断实验可以解释主结果，但若产生新主张，应登记为新一轮研究问题。

## 完成

`experiments/results.md` 区分事实结果、计算推导和解释；`evidence.md` 将声明映射到 run ID、原始产物和分析定位。完成状态允许 `supported`、`refuted`、`mixed` 或 `inconclusive`，不得只允许正结果。

结果文件使用 `Outcome: supported|refuted|mixed|inconclusive` 记录核心问题终局。
