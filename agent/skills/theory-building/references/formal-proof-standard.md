# 形式证明标准

## 1. 证明对象

先明确理论类型：概率/统计界、优化性质、复杂度、识别性、信息论界、博弈均衡、系统安全不变量、不可行性或其他形式命题。每个符号、域、量词和随机性来源必须在定理前定义。

## 2. 定理记录

每个 `T<n>` 至少包含：

- 精确陈述与量词；
- 全部假设及其现实含义；
- 与最近理论结果的差异；
- 非平凡性与科学相关性；
- 依赖的引理 DAG；
- 完整证明位置；
- 可观察推论；
- 失效边界与已知反例。

证明不得引用待证明结论、未定义事实、经验结果或模型自述作为演绎步骤。使用外部定理时核验原始来源的精确前提。

## 3. 构建循环

```text
定义与假设
→ 小命题/引理
→ 主定理
→ 逐步证明
→ 假设去除与反例搜索
→ 边界/紧性分析
→ 经验推论
→ 独立 proof-skeptic
```

证明失败时允许收缩结论、增加有现实依据的假设或拒绝理论；所有变化版本化。不得加入只为使证明成立、但现实实验无法满足的假设后仍声称解释真实系统。

## 4. 验证层级

- 手工证明：逐步列出推理、依赖和使用的外部结果。
- 符号/数值检查：用于发现代数错误与反例，不构成一般性证明。
- 有限枚举/模型检查：只证明声明覆盖的有限域。
- 证明助理：适合可形式化核心；保存版本、依赖和可重放脚本。机器接受不自动证明定理具有科学意义。

## 5. 独立审计

`proof-audit.md` 必须记录 Reviewer role、Reviewer model、Verification level、Independent reconstruction、Independence statement、逐定理决定和未解决问题。审计者须在不继承原证明推导链的上下文中独立重构关键步骤；同一模型仅切换角色不构成强独立性。Verification level 使用 `manual-reconstruction|machine-checked|dual-path`；适合形式化且成本合理时优先采用机器检查，否则明确未机器验证的边界。审计者优先寻找：量词交换、隐藏正则性、边界遗漏、条件概率混淆、渐近结论被外推到有限样本、松弛界无信息、循环引理和反例。

只有所有核心定理为 `pass`，且至少一个非平凡经验推论映射到冻结实验，理论型门禁才能通过。
