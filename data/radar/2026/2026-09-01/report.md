## 01｜AstaBench：科研 Agent 不能只会查论文

**原论文：** [AstaBench: Rigorous Benchmarking of AI Agents with a Scientific Research Suite](https://arxiv.org/abs/2510.21652)｜ICLR 2026 Oral

### 1 研究动机

科研 Agent 经常被演示成“输入问题，输出一份带引用的报告”。但真实科研不止是检索和写作：还包括定位文献、理解全文、复现实验、分析数据、提出假设、设计实验、执行代码以及解释失败。只测其中一个环节，很容易把“会搜索”误认为“会科研”。

现有评测还有三个混杂因素。第一，不同 Agent 使用的搜索工具不同，结果差异可能来自检索后端，而不是模型能力。第二，更高预算可以通过反复采样抬高分数，不报告成本就无法公平比较。第三，联网搜索结果会随时间变化，同一个 Agent 在不同日期运行可能看到不同文献，导致评测不可复现。

AstaBench 的重要性不只是增加了一个榜单，而是提出一套更严格的科研 Agent 评测观：**评测对象必须覆盖科研流程，工具环境必须受控，性能必须和成本一起解释。**

> **理解全文需要的概念：** benchmark suite 不是一道任务，而是一组测量不同科研环节的测试；受控工具是所有 Agent 共用且可冻结结果范围的搜索与执行接口；Pareto frontier 表示在给定成本下，没有其他系统能同时更便宜且更准确的方案集合。

### 2 方法介绍

#### 从单点能力扩展到完整科研流程

AstaBench 汇集 11 个 benchmark、2400 多个问题，覆盖四类能力。文献理解包括论文查找、全文问答和综述表格生成；代码与执行包括数据科学编程和论文实验复现；数据分析要求从给定数据中发现并验证规律；端到端发现则要求 Agent 从研究想法出发，完成计划、代码、实验、分析和报告。

这些任务并非都用同一种评分方式。答案可以唯一确定的任务使用程序化评价；开放式综述、分析和报告则依据 rubric 评价。这样做比统一交给一个 LLM Judge 更合理，但也意味着不同子任务分数只能先在各自语境中解释，不能把宏平均值当成单一、纯净的“科研能力”。

#### 冻结搜索环境，避免未来信息污染

论文提供 Asta Scientific Corpus。它允许评测者限制 Agent 只能检索某个截止日期以前的论文，因此今天和半年后运行同一测试时，Agent 面对的知识边界可以保持一致。这解决了联网科研评测最难控制的变量之一：搜索结果随时间变化。

代码任务在 Computational Notebook 中执行。不同 Agent 获得相同工具接口和任务允许的工具子集。提交结果时还会记录 Agent 是否开放、底层模型是否固定版本、工具是否受控，从而区分“方法可复现”“只能复核输出”和“黑盒 API”几种不同可信度。

#### 把准确率和成本放在同一张图上

评测工具根据固定价格快照重新计算模型调用成本，防止 API 后续降价改变历史比较。论文同时报告均值、标准差、每题成本和质量—成本 Pareto frontier。其核心思想是：一个 Agent 如果通过多走十倍步骤获得少量提升，不应被简单宣布为更好。

#### 核心实验：科研能力远未形成完整闭环

- 在能够覆盖全部任务的系统中，使用开放权重模型的最佳开放 Agent 总分只有 **11.1%**；使用闭源模型的 Asta v0 达到 **53.0%**。这说明底层模型仍然显著影响科研 Agent，但开放系统与闭源能力之间存在很大缺口。（Table 4，PDF 第 18 页；正文第 9 页）
- Asta v0 比使用 GPT-5 的通用 ReAct 高约 **9 个百分点**，即 53.0% 对 44.0%。不过 Asta v0 需要专门工具和工程设计，因此这个结果支持的是“任务化工具有价值”，而不是“某种 Agent 架构普遍更强”。（正文第 7–9 页）
- ReAct 加 GPT-5-mini 得到 **32%**，距离最高结果相差 21 个百分点，但每题约 **0.04 美元**，成本低一个数量级。这说明只看最高分会掩盖更适合大规模研究的经济方案。（Figure 2、Table 4，PDF 第 8、18 页）
- 端到端实验的单步完成率最高接近 **70%**，但全部步骤都成功的比例最高只有 **5%**。长链任务会乘法累积错误，因此“多数步骤做对”仍可能对应“完整研究几乎做不成”。（Table 20，PDF 第 41 页）
- GPT-5 并没有稳定提升所有专用 Agent；部分专用工作流换用 GPT-5 后反而下降。论文提出一种可能解释：新模型或许针对常见 ReAct 工作流优化，却不一定适配定制编排。这个现象有启发性，但目前不是因果证明。（正文第 9–10 页）

### 3 总结归纳

> **核心贡献：** AstaBench 把科研 Agent 评测从“回答几个科研问题”提升为“在受控工具和成本条件下覆盖完整科研流程”，并用冻结语料、统一接口和成本归一化减少常见混杂因素。

> **证据边界：** 11 个 benchmark 的评分机制和难度不同，宏平均会压缩任务差异；部分开放任务依赖模型评分；许多商业 Agent 无法运行全部任务，因此完整横向比较仍不充分。工具受控提升了内部可比性，但与真实研究者自由选择工具的环境存在距离。

这篇论文最值得迁移的思想是：**Agent 评测首先是一项实验设计问题。** 在比较模型之前，应固定工具、知识截止日期、预算和任务接口，并分别报告子能力和端到端成功率。否则观察到的提升很可能来自更多搜索、更贵模型或更有利的外部工具。

一个直接可执行的后续实验是做“模型—脚手架交叉互换”：固定同一模型比较 ReAct 与专用科研工作流，再固定脚手架替换不同模型，同时记录成功率、调用次数、总成本和失败阶段。如果专用 Agent 的优势主要来自与特定模型的适配，交叉互换后排序应明显改变；如果优势来自稳健的流程设计，收益应跨模型保持。

另一个值得验证的问题是宏平均是否掩盖关键瓶颈。可以根据完整科研任务的依赖关系，为每个环节估计失败传播概率，再比较“平均子任务分数”和“预测的端到端成功率”。如果二者相关性低，就应将评测重点从平均能力转向最薄弱环节和错误累积。

## 02｜Gaia2：真实环境不会等 Agent 思考完

**原论文：** [Gaia2: Benchmarking LLM Agents on Dynamic and Asynchronous Environments](https://arxiv.org/abs/2602.11964)｜ICLR 2026 Oral

### 1 研究动机

许多 Agent benchmark 的世界是静止的：Agent 调用一次工具，环境返回结果，然后安静等待下一步。但真实应用会在 Agent 思考时继续变化。邮件可能到达，预约可能被修改，服务可能超时，工具可能随机失败，另一个 Agent 也可能同时采取行动。

静态任务主要测“在已有信息下选择正确工具”。动态任务还要求 Agent 维持时间意识、响应新事件、处理歧义、抵抗噪声并协调多个参与者。一个推理更强但每次思考很慢的模型，在静态 benchmark 上可能占优，在有截止时间的任务中却可能直接失败。

Gaia2 因而提出一个重要修正：**Agent 能力不是脱离环境的模型属性，而是模型、延迟、编排方式和环境动力学共同产生的系统行为。**

> **理解全文需要的概念：** 异步环境表示时间与事件不依赖 Agent 的调用节奏而继续推进；event DAG 用有向无环图表达事件触发顺序和依赖；write-action verifier 不要求 Agent 走固定轨迹，而是检查它实际改变环境的动作是否与目标状态一致。

### 2 方法介绍

#### ARE：让环境拥有自己的时间线

论文先构建 Agents Research Environments（ARE）。环境由应用、工具、事件、通知和场景组成。场景给定初始状态和事件图；Agent 行动、用户消息、定时器和外部变化都可以触发新事件。模型生成答案时，模拟时间仍然向前推进，因此推理延迟会真正影响结果。

ARE 还能保存完整执行轨迹，并在图形界面中查看事件是否触发、Agent 在何时做了什么以及失败发生在哪个依赖节点。它不仅用于跑分，也支持构造场景、调试 Agent 和生成可用于强化学习的逐动作反馈。

#### 七类能力不是七个孤立标签

Gaia2 包含 800 个独立人工场景，并通过 Noise 和 Agent-to-Agent 两类环境增强得到总计 **1120 个场景**。五类核心任务分别测试连续执行、跨应用搜索、主动澄清歧义、适应环境变化和时间约束；两类增强测试工具错误与无关事件下的鲁棒性，以及通过其他 Agent 间接使用工具的协作能力。

作者没有强行构造“组合能力”类别，因为真实任务天然同时涉及搜索、执行和时间。各分类只表示主要压力来源，不意味着能力彼此正交。这种处理比把每个任务贴成唯一能力标签更诚实。

#### 用动作语义验证，而不是要求固定操作序列

每个场景都带有人工编写的正确动作图。Verifier 先比较必要工具调用，再检查参数语义、动作依赖顺序和时间约束。只要 Agent 完成等价的状态改变，就不必复现参考轨迹。

作者在 450 条人工标注轨迹上检查 Verifier，报告 **0.99 precision、0.95 recall**。论文也公开讨论了早期 Verifier 被 Agent 利用的问题，并加入风格检查。这一点很重要：可验证奖励不是天然可靠，Verifier 本身也必须接受对抗式测试。

#### 核心实验：更深思考可能错过时间窗口

- GPT-5 high 的总体结果最高，为 **42.1% pass@1**；开源模型中 Kimi-K2 约为 **21%**。没有模型在所有能力上领先，说明单一总分无法代表部署表现。（Table 2，PDF 第 7 页）
- 把模型生成延迟移除后，Claude 4 Sonnet 在 Time split 上从 **8.1% 提升到 26.7%**，GPT-5 high 从 **0.0% 提升到 34.4%**。这表明部分“推理失败”其实是系统来不及行动，而不是不知道怎么做。（Figure 8，PDF 第 9 页）
- 强推理模型在 Execution 上更好，却可能在 Time 上更差，形成反向尺度趋势。论文据此主张 Agent 需要 adaptive compute：简单、紧急任务少想，复杂任务再调用深推理。（Section 5.2，PDF 第 8–9 页）
- 平行工具调用减少墙钟时间和 token，但没有提高成功率。这排除了“所有失败只是顺序脚手架太慢”的简单解释，同时说明并行本身不等于更好决策。（Table 6，附录 PDF 第 30 页）
- 增加协作 Agent 数量没有持续改善成本归一化表现；异构强弱模型配对有时比单纯增加同类 Agent 更有效。协作收益取决于任务分解和角色能力，而不是 Agent 数量。（Table 3、Figure 10，PDF 第 9–10 页）

### 3 总结归纳

> **核心贡献：** Gaia2 把时间、外部事件、噪声和协作纳入可复现 Agent 环境，并证明模型准确率、推理延迟、成本和编排之间存在不可忽略的权衡。

> **证据边界：** 场景发生在一个手机式模拟环境，时间任务最长约五分钟，仍不能覆盖长周期真实工作；能力分类并非严格独立；Verifier 假设关键写操作可以与 oracle 动作匹配，等价动作覆盖仍可能不完整。模型 API 的服务波动也会混入系统结果，但这恰好是部署现实的一部分。

这篇论文带来的关键启发是：**上下文长度、推理强度和 Agent 性能不能脱离时间预算讨论。** 增加思考 token 可能提高单步正确率，却降低在截止时间前完成任务的概率。未来评测至少应同时报告任务成功率、决策延迟、墙钟时间、成本和超时类型。

一个可执行实验是构造相同任务的多组截止时间，并让同一模型使用固定浅推理、固定深推理和基于剩余时间动态切换三种策略。若 adaptive compute 确实有效，它应在严格时限下接近浅推理的速度，在宽松时限下接近深推理的准确率，并形成更优的成功率—成本—延迟 Pareto frontier。

还可以把环境变化强度作为连续变量：逐步提高无关通知、工具失败率和关键事件频率，绘制性能退化曲线。这样测到的不只是某个噪声设置下的分数，而是系统在多大扰动下开始失稳，以及失败来自感知遗漏、计划过期还是恢复策略不足。

## 03｜Shoot First, Ask Questions Later?：Agent 应该问什么，而不只是想多久

**原论文：** [Shoot First, Ask Questions Later? Building Rational Agents that Explore and Act Like People](https://arxiv.org/abs/2510.20886)｜ICLR 2026 Oral

### 1 研究动机

Agent 面对信息不完整的任务时，可以继续行动，也可以先提问。真正困难的不是“会不会问”，而是决定**哪个问题最能减少当前不确定性，以及获得信息是否值得延迟行动**。语言模型常能生成听起来合理的问题，却可能重复询问已经知道的事实，或获得的信息对最终决策没有帮助。

论文用协作版 Battleship 把这个矛盾变成可测量任务。Captain 看不到完整棋盘，需要决定提问还是射击；Spotter 看得到棋盘，但必须理解自然语言问题并准确回答。任务同时包含空间推理、上下文指代、信息价值和探索—行动权衡。

作者没有只比较更大的语言模型，而是把语言模型与 Bayesian Experimental Design（贝叶斯实验设计）结合。核心观点是：**语言模型适合提出假设和生成候选，显式概率推断适合维护不确定性并选择最有信息量的行动。**

> **理解全文需要的概念：** belief 是根据当前证据仍可能为真的世界状态分布；expected information gain（EIG）衡量一个问题的答案预计能减少多少不确定性；Sequential Monte Carlo（SMC）用一组带权样本近似无法穷举的状态空间。

### 2 方法介绍

#### 用粒子表示“棋盘可能是什么样”

Captain 根据已经看到的命中、未命中和问答历史，维护一组可能棋盘。每个棋盘样本都有权重；Spotter 回答后，与答案一致的样本权重上升，不一致的样本不会被完全删除，因为回答者可能出错。系统用参数 ε 表示回答或语言转代码发生翻转错误的概率。

精确枚举所有合法棋盘代价太高，因此论文用 SMC 反复采样和重加权。这个做法把语言交互转化为可更新的世界模型：Agent 不只是把对话塞回上下文，而是显式记录“哪些状态还有多大可能”。

#### 让语言模型生成问题，让信息论负责挑选

纯 LM 策略直接决定是否提问、问什么和射击哪里。Bayes-Q 策略先让模型提出多个自然语言候选问题，再转成可在棋盘样本上执行的函数，计算每个问题的 EIG，选择预计最能区分候选棋盘的问题。Bayes-M 根据 belief 选择命中概率最高的位置；Bayes-D 决定继续提问还是立即行动。

这种分工避免了两个极端：完全符号化系统难以理解开放语言，完全依赖 LM 又缺少稳定的不确定性计算。论文实际检验的是“生成式模型 + 结构化推断”能否胜过单纯扩大模型。

#### 人类数据提供行为基线

作者招募 **42 名参与者**，收集 126 局人类—人类轨迹，并对 931 个问题建立无争议的 gold answer。人类回答准确率为 **92.5%**。标注还区分只依赖棋盘的问题和需要理解对话指代、模糊表达或当前策略的问题，从而可以定位语言模型究竟在哪类信息交互上失败。

#### 核心实验：结构化推断可以补偿较弱模型

- 在 15 个模型的 SpotterQA 上，直接生成代码读取棋盘比基础回答平均提高 **13.2 个百分点**；CoT 加代码提高 **14.7 个百分点**，且 Mann–Whitney U 检验得到 p<0.001。收益说明把空间判断外包给可执行表示能够减少语言模型的感知错误。（Figure 3，PDF 第 6 页）
- 人类在简单问题和复杂语境问题上的准确率接近，分别为 92.8% 和 91.9%；GPT-4o 从 72.8% 降到 60.4%，Llama-4-Scout 从 68.0% 降到 54.0%。当前模型的主要弱点不只是棋盘推理，还包括指代、语用和上下文依赖。（Figure 3，PDF 第 6 页）
- 加入完整 Bayes 问题、行动和决策策略后，Llama-4-Scout 的 targeting F1 从 **0.367 提升到 0.764**，GPT-4o 从 **0.450 提升到 0.782**。弱模型配合外部推断可以超过纯 GPT-5 策略。（Figure 4，PDF 第 7–8 页）
- 贝叶斯提问让每个问题的 EIG 最多提高 **0.227 bit**，达到可实现信息上限的 **94.2%**，同时减少信息增益为零的重复问题。这直接支持“问得更有用”，而不只是最终胜率偶然提高。（Figure 4、Table 4，PDF 第 8、39 页）
- 完整策略对人类的配对胜率达到约 **82%–83%**，对纯 GPT-5 达到 **67%**；Llama-4-Scout 的总实验成本约为 GPT-5 的 **1%**。在另一项 Guess Who? 游戏中，成功率仍提高 28.3–42.4 个百分点，提供了有限但有价值的跨任务复现。（Table 5、Table 9，PDF 第 40、45 页）

### 3 总结归纳

> **核心贡献：** 论文把 Agent 的主动提问形式化为带噪声的贝叶斯实验设计，并展示语言生成与显式不确定性推断结合后，较弱模型可以用更低成本做出更有信息量的提问和行动。

> **证据边界：** Battleship 和 Guess Who? 都有可枚举、规则明确的隐藏状态；真实科研、诊断或软件任务很难手工定义完整 world model。实验使用固定错误率 ε，而不同信息源的可靠性会随问题变化；GPT-5 因成本没有覆盖所有策略组合；“超过人类”只指该受控游戏指标，不能外推到一般理性。

这篇论文最重要的研究启发不是“给 Agent 加一个贝叶斯模块”，而是把信息获取拆成三个可评测变量：候选问题是否覆盖有效假设、答案能减少多少不确定性、提问收益是否超过等待成本。许多搜索 Agent 只测最终答案，因而无法区分“搜索很多”和“每次搜索都有效”。

一个可执行后续实验是把 EIG 思路迁移到文献检索。先定义若干互斥研究假设，让 Agent 为每次搜索预测结果可能如何改变当前 belief；再比较纯 LM 搜索、基于检索相关性的搜索和近似 EIG 搜索。在相同查询预算下，若 EIG 策略能更快排除错误假设、减少重复查询并提高最终结论校准度，就说明该思想可以超越封闭游戏。

另一个关键问题是如何学习而不是手工编写 world model。可以让模型从历史轨迹生成一组结构化假设，用独立验证器检查假设与证据是否一致，再以粒子权重表示置信度。实验应分别改变假设覆盖率和验证器错误率，观察性能在哪个阈值后崩溃，从而判断系统收益到底依赖语言模型提出好假设，还是依赖后端推断足够准确。
