# 论文精读

目标是能解释、复现核心推理并识别适用边界，而不是改写摘要。开始前读 [精读与图示](references/deep-reading.md)。

输入：已核验的论文版本、全文、当前待回答问题、目标读者的已有知识以及必要代码/数据。输出：读者能追踪的论文讲解、可定位证据、未解决理解问题、正文可用方法图。读者背景优先采用用户要求；未说明时写明合理假设，不把专业读者或零基础固化为所有请求的默认值。

精读结果在正文组织为三部分：

1. **研究动机**：从具体任务和既有方法的处理过程出发，让读者看见问题；补齐必要背景后引出科学问题，区分作者叙述与真正证据。
2. **设计方案**：先直觉、再逐步操作与图解、再形式化。用同一例子走通原始输入、处理中间量、训练/推理输出；关键符号、计算和梯度含义不能省略。实验按“检验什么—比较什么—观察什么—允许推出什么”组织；必要附录中的机制写入正文。
3. **启发探索**：先重述作者真正改变的步骤及证据，再分析边界、近邻异同、可复用机制和待验证探索。不要在读者理解原方法前以新颖性审判取代讲解。

每份记录区分“取得全文”“实际读到哪里”“哪些机制已通过理解核验”。未读/不可访问/未理解分别记录。全文文件和填满模板不是完成证据。

关键事实附章节、公式、表格、图或代码定位。取舍按论文类型：理论需检查假设和证明中真正承担结论的步骤；系统需检查瓶颈、资源口径和故障；测量需检查构念、采样和误差。不得为了模板强行增加训练、GPU 或因果中介。

交付前做两种不同核验：回到原文检查解释正确；只用正文检查目标读者是否获得推演所需的前提。若必须借助未介绍的术语、外部公式或评审自己的知识才能答题，标记解释缺口并重写对应路径。回答“若条件改变会怎样、哪个实验支持、哪里无法判断”须有正文依据，不把流畅回答或长篇内容当作可理解的证据。
